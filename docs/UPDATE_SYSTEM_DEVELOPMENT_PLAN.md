本輪來源實施另見[體檢修正與保留驗收對照](AUDIT_REMEDIATION_20261029.md)
及[更新來源發布流程](UPDATE_PUBLISHING.md)。它補上 Windows 首次依賴自動準備、
精確產品檔案政策、固定產物驗收與發布、客製程式阻擋，以及體檢修正與行為保留重構。
本輪交付來源及測試；網上渠道、三號安裝與既有工作室更新仍屬獨立階段。

[開發計劃索引](DEVELOPMENT_PLAN.md) · [開發流程](DEVELOPMENT.md) · [既有生命週期](INSTALL_UPDATE_FLOW.md) · [Agent 合約](AGENT_CONTRACT.md)

日期：2026-10-29。產品方向已選定，本文件保留完整開發範圍、責任、次序及驗收條件；已進入原生安裝器 v2 的來源實作，現況及未完成項目見第十三節。這是為工作室開發更新功能的計劃，不是替任何現有客戶執行更新的操作單。

目標是讓多個客戶各自擁有獨立工作室與資料，透過同一更新入口管理工作室核心、通用 AI 服務及客戶專用模組。開發端先驗證固定版本，客戶後台提前準備適用的更新；客戶選擇套用時，只完成必要保護、版本切換及啟動核對。

## 一 產品決定與第一版範圍

1. 核心與 AI 服務從第一版起就是獨立的更新單位。可以一起發布相容組合，但不強迫每次重新部署全部服務。
2. 每個客戶工作室有自己的核心版本、服務清單、私人資料、憑證、更新狀態及操作紀錄。五個客戶代表五個獨立工作室，不是同一家公司內的五個帳號。
3. 預設體驗為自動檢查及背景準備，擁有人或獲授權維護者選擇套用。首次安裝或接入受管更新時固定可信來源及更新政策；發布新版不等於客戶已授權立即切換。
4. 左下角保留一個更新入口，只顯示該工作室有權取得、已安裝或明確選擇啟用、且符合版本條件的更新。普通成員依權限查看狀態，不能改變全工作室的服務版本。
5. 發布前完成相容性、回歸、升級與恢復測試。客戶安裝不重跑開發測試、不新增測試對話或發送驗收訊息；只做套用所需的自動核對。
6. 第一條實作路線為原生工作室，先驗證 Windows 本機受管服務。雲端原生服務、Sites 接駁及其他宿主各有實際套用 adapter；未支援者如實顯示能力限制。
7. 首個接入的真實 AI 元件為 BlueSAI 客服。流水線與影片 AI 使用同一套擴充合約；本計劃不連帶開發它們的業務功能。

「大更新／小更新」可作產品說明，但執行必須依受影響元件、相容性、資料遷移和所需停頓判斷。一行資料格式變動也可能需要完整遷移；大量介面調整則可能只需保存後重新載入。

## 二 持續演進與調整原則

Blueprint 與 BlueSAI 都在開發階段。既有架構、核心邊界、介面、開發規則及版本策略可隨新需求、AI 能力及運行環境調整；不把歷史決定當成永久限制。需要時可以作小型、中型或大型調整，並同步修改受影響的合約、文件、遷移和驗收。

調整前先向使用者說明以下內容，再在已授權範圍內執行：

- 要改哪項原有邏輯，以及新需求為何需要這項改變。
- 影響哪些來源、接口、服務、使用者操作或資料格式。
- 舊功能如何轉到新設計，已有資料、權限、自訂設定與草稿如何延續。
- 如何驗證、分批交付及處理失敗。

預先告知不是每一步重新請求相同批准。遇到新的產品取捨、未授權部署或資料處置時，才確認必要決定。架構可以更換，資料、身份、隱私及已完成工作仍須保護。使用者已授權按次序開發公開來源與測試；這項授權不包含部署現有工作室。

| 需要演進的既有做法 | 本計劃的調整方向 |
| --- | --- |
| 更新助手以準備、交接及 AI 操作為主 | 補上真正的背景準備與受管套用能力；保留人工／AI 接續路線 |
| Agent 登記換版與外部程式替換分開 | 用同一工作室更新操作協調兩者，分別保存與讀回結果 |
| AI 模組獨立更新留待較後階段 | 第一版就建立獨立元件、依賴與套用合約，先由客服接入 |
| 過往沒有常駐程式更新器 | 明確新增只負責更新的受管服務；不把它擴大為通用 AI 執行器 |
| 既有介面沒有更新提示入口 | 增加一個低干擾入口，沿用視覺系統；不靠公司資料輪詢檢查新版 |
| 有些客服任務在設定改變或停止時直接取消 | 設計明確的等待、取消、恢復與提示規則，再同步修改客服合約及回歸 |
| 人工／AI 主導的既有更新驗收 | 保留按風險選擇的要求，將客戶安裝所需核對自動化；新平台或渠道接入的另行驗收仍保留 |

以下保留原規劃時的來源能力分工，作為實作責任及缺項的起點；v2 已完成的來源能力見第十三節。每次交付仍須核對所選來源及未提交差異，不能用本表代替特定實例的驗收。

| 項目 | 可沿用的基礎 | 需要補齊 |
| --- | --- | --- |
| Blueprint 更新紀錄 | `blueprint_library/lifecycle.py`、`operations.py` 的階段、操作 ID、計劃摘要及版本檢查 | 下載與套用的持久子狀態、實際 executor、崩潰後接續 |
| Blueprint 資料保護 | `maintenance.py` 的資料 lease、備份、遷移演練與失敗副本 | 跨核心及外部 AI 資料域的一致切換協調 |
| Blueprint 更新介面 | `library_web/update.js` 的備份、排版接續及更新指示 | 更新清單、背景準備狀態、權限化套用與結果顯示 |
| Agent 套件 | 同 ID 升級、歷史、設定保留與工作快照 | 真正 runtime／資產換版及模組生命週期 adapter |
| BlueSAI 發行 | 固定來源包、release metadata、inventory、SHA-256 及私隱檢查 | 接入共用發行合約、適用性判斷及背景準備 |
| BlueSAI 安裝與發送 | 私人安裝 journal、同 Agent ID 接駁、持久去重及未知發送狀態 | 更新暫停協定、草稿恢復、來訊接續及完整版本追蹤 |
| 客戶版本隔離 | 原生公司資料目錄及 BlueSAI 單商戶程序可作獨立部署基礎 | 每工作室的受管部署單位及版本選擇；目前不能宣稱完整多租戶更新能力 |

已有測試 runner 用於開發驗證；客戶端更新 executor 用於已授權的安裝切換，兩者責任不同。沿用共用開發 harness，不把它複製到每個客戶，也不把計劃檢查誤當部署引擎。

## 四 架構與版本隔離

```text
各維護來源
  → 建立固定產物與相容組合
  → 開發及候選環境驗證
  → 發行目錄與可信產物儲存
  → 各工作室的更新協調器
  → 背景準備 → 等待套用 → 切換 → 同工作室讀回
```

發行目錄提供版本、依賴、改動摘要、適用平台、完整性及可信來源資料。客戶專用套件使用受存取控制的私人目錄，不能由公開清單或可猜的下載位置洩漏客戶內容。

每個工作室保存已安裝、已準備、正在套用、實際啟用與可回復版本。主機可以共用不可變的通用產物快取；資料、憑證、渠道、可寫設定及更新 journal 各自獨立。客製產物依其授權隔離快取。

第一版優先採每工作室獨立的受管服務與版本目錄，可共用同一台機器。A 套用時不能覆蓋 B 正在執行的程式。需要共用程序服務多個客戶時，必須先實作並驗證版本路由及資料隔離；五個登入帳號不能代替這項能力。

套用控制需在被更新的服務停止後仍可繼續。以既有主機服務管理方式提供最小更新執行器，不讓待替換的 Web 程序獨自承擔自身重啟與恢復。其權限限於已綁定的工作室與元件，不接受前端任意路徑、命令或目標身份。

客戶可以在支援期間保留舊版。發行目錄需定義支援的核心／模組組合、允許的升級路線、撤回版本與支援期限；不能以版本號較大就推定相容。支援期限及緊急修補政策在啟用正式渠道前確定，不默認強制更新。

## 五 三類來源各自負責的工作

### 藍圖工作室

Blueprint 維護共用更新能力及合約，負責協調，不接管各 AI 的業務實作。

| 工作 | 具體交付 |
| --- | --- |
| 工作室身份與權限 | 從已驗證身份判斷可讀、可準備、可套用的目標；保護公司邊界及原 Agent ID |
| 元件與依賴登錄 | 核心、Agent、資產、adapter、渠道橋接與客製模組的已安裝版本及相容關係 |
| 更新發現與背景準備 | 可信目錄、適用性判斷、下載去重、空間檢查、固定 runtime／依賴準備、驗證、獨立暫存及失敗重試 |
| 更新協調與持久紀錄 | 同一工作室的排他套用鎖、operation／digest、步驟收據、未知結果讀回與中斷接續 |
| 核心與宿主 adapter | 真正資產及服務替換、版本讀回、啟動恢復；按平台宣告能力 |
| 資料與草稿保護 | 沿用維護生命週期；新增受影響分頁的保存協調，不把排版草稿當成所有表單已保存 |
| 統一介面 | 左下角提示、影響摘要、套用／稍後、阻礙原因、完成及失敗狀態 |
| 共用擴充合約 | 元件檢查、暫停、切換、恢復、狀態及結果格式；為新 AI 提供合成參考 adapter |

通用更新器只檢查發行 metadata 與必要安裝狀態，不藉機輪詢或上傳公司正文。跨客戶維護視圖如要集中呈現，限獲授權的版本、能力及結果摘要，採按需存取或明確啟用的回報。

### BlueSAI 客服 AI

BlueSAI 維護客服運行、資料及渠道接續，接入 Blueprint 合約，不另建另一套總更新中心。

| 工作 | 具體交付 |
| --- | --- |
| 客服元件發行 | 客服程式、介面資產、渠道橋接、schema 與宿主接口的版本及依賴；固定已測產物 |
| 套用 adapter | 狀態讀取、暫停接新工作、等待在途工作、切換、恢復及實際版本回報 |
| 生成與人工工作 | 定義可完成、可取消及可恢復狀態；保留人工接手與未送出草稿 |
| 來訊與發送接續 | 有可靠能力才持久暫存來訊；恢復按事件 ID 去重；結果未知先查回，不盲目重送 |
| 工作版本 | 追蹤程式、規則／提示、模型設定與知識來源；已撤銷權限及人工控制即時生效 |
| 客服資料保護 | 對話、知識、設定、客服及橋接資料庫、必要渠道登入與待處理工作分域保護 |
| 原實例延續 | 同 Agent ID、設定、歷史與有效連線；需要重新驗證的 grant 如實呈現，不偷開自動發送 |
| 客服合成驗收 | 忙碌生成、人工發送、未知結果、斷線、重啟、草稿、升級及回退案例 |

第一版同一客戶的同一客服服務採單一啟用版本：先等工作到達安全邊界，再切換，新工作使用新版。不同客戶可同時使用不同版本。讓同一客服的新舊 runtime 並行屬後續能力，不能以現有工作快照宣稱已具備。

一般停止與更新排空須分開：v2 受管入口先暫停新工作，等待在途生成、發送及學習完成，才正常停止；普通非受管停止仍沿用自身取消語意。需要改變取消或 grant 失效行為時，先按第二節說明並同步回歸。沒有可靠來訊暫存時，介面須說明短暫服務中斷，不能保證零停機或不漏訊息。

### 客戶專用模組與未來 AI

客戶專用程式由其經核實的私人維護來源負責；可重用的通用模組可有自己的公開來源。公司知識、規則值、憑證與工作資料始終留在私人 runtime，不能混入程式包。

| 工作 | 具體交付 |
| --- | --- |
| 模組邊界 | 穩定模組 ID、負責來源、適用工作室、版本及核心／其他模組依賴 |
| 客製方式 | 優先使用設定與擴充接口；需要修改核心時保留明確差異、維護責任與配對驗證 |
| 發行與存取 | 私人套件、授權檢查、固定產物、獨立發行節奏與更新摘要 |
| 生命週期接入 | 實作相同 adapter 合約，宣告資料域、長工作、安全切換點與恢復方法 |
| 設定與資料遷移 | 官方預設、客戶覆寫及資料版本分開；明列欄位移除、變更與保留策略 |
| 模組驗收 | 驗證支援的版本組合、私人資料隔離、長工作及更新失敗；不依賴客戶現場試錯 |

影片生成、流水線等長工作若使用外部服務，保存可查回的工作 ID 與狀態；重新啟動不代表重新提交。無法恢復的工作要等完成或明確處理，不能以重新執行代替接續。

## 六 共用合約的開發內容

以下是完整合約的開發責任，包含已有與待補能力；不能把整張表當成現有 API。v2 的實際 CLI、格式與限制見[受管安裝器](MANAGED_INSTALLER.md)及[發行渠道合約](MANAGED_RELEASE_CHANNELS.md)，其餘依分階段驗收完成。

| 合約 | 必需內容 |
| --- | --- |
| 發行描述 | 元件 ID、版本、來源 pin、產物 SHA-256、簽章、平台、固定 runtime／依賴清單與完整性資料、大小、發布／撤回狀態、改動摘要 |
| 相容性 | 支援核心與依賴範圍、已測組合、資料讀寫格式、遷移路線、可回復範圍、所需能力及停頓 |
| 工作室安裝狀態 | 私人工作室 ID、已安裝模組、實際啟用版本、準備版本、客製設定版本、渠道及更新政策 |
| 套用操作 | 目標身份、from／to 組合、計劃摘要、operation ID、並行控制、資料域、步驟結果、恢復位置 |
| 元件 adapter | 檢查現況、報告忙碌原因、暫停新工作、等候或保護在途工作、套用、恢復接收、讀回版本及故障 |
| 發布證據 | 與固定產物綁定的檢查指紋、支援平台與升級起點；證據變動時重新判斷適用性 |

簽章與雜湊分開處理：雜湊核對內容，可信金鑰驗證來源。需設計可信來源初始設定、金鑰輪換、失效／撤回檢查及私人套件授權。下載中斷可以重試；只有伺服器與檔案驗證允許時才續傳。通過驗證的候選不能在套用時被浮動分支或重新建置結果替換。

交付物須能在所選平台的已準備環境執行。只有來源封存檔不足以代表安裝就緒：v2 使用首次接入時固定的現有 Python，以及操作者明確提供的 Node `>=24.22.0 <25`，核對實際版本與執行檔，不自動下載 runtime。未來若提供預先取得的環境，仍須另有固定清單及完整性驗證。準備使用隔離的版本目錄，不覆寫其他工作室共用的系統 runtime；套用時不解析浮動依賴、不臨時下載編譯另一個候選。

來源收據沿用既有生命週期；更新準備狀態作版本化擴充。現有 operation 的 stage 驗證有限定值，不能直接塞入新字串而宣稱相容。設計新子狀態與舊工具讀取行為，再同步 API、MCP、文件與測試。

多元件更新是一項有先後次序的操作，不假設跨程序、跨資料庫可原子提交。先固定完整依賴組合，每一步持久記錄並獨立讀回；部分成功須保留實際組合，所有必要元件確認前不能報整體成功。v2 尚未實作未知部分結果的自動接續／復原，這類操作保留 `recovery_required`，不能把狀態保存當成恢復引擎已完成。

## 七 更新流程與失敗處理

### 背景準備

1. 從可信發行目錄查詢，按工作室授權、已安裝元件與支援組合選擇更新。
2. 固定更新計劃；模組需要新版核心時，合併成一次可理解的更新，說明影響，不默默更改核心。
3. 下載至獨立暫存位置，核對已準備的固定 runtime 與依賴，以及空間、完整性、來源與平台條件。這時不替換運行程式、不遷移正式資料。
4. 全部必要產物及運行環境已準備並驗證後顯示「更新已準備好」。沒有實作對應宿主 adapter 或候選不再有效時，不能顯示可套用。

### 客戶選擇套用

1. 驗證操作者及工作室身份，取得該工作室的排他套用權；重複點擊沿用同一操作。
2. 重查實際版本、候選撤回狀態及依賴，防止準備後現況已改變。
3. 通知受影響分頁保存。保存包括伺服器寫入確認或可恢復草稿，不把按過保存按鈕視為成功；無法確認的活躍分頁須延後或按明確政策處理。
4. 暫停新的受影響工作，等待既有工作完成或到達已驗證的恢復點。逾時說明阻礙，不能強制丟棄工作。
5. 依資料域完成當前一致的保護。沿用仍有效的備份、還原證據與私人副本；變更後覆蓋失效才重做需要的部分。核心備份不自動涵蓋外部客服或渠道資料。
6. 依 adapter 套用固定產物及必要遷移，保留網址、身份、資料與元件 ID；驗證相容的 UI／API 組合，避免新舊資產混載。
7. 讀回真正載入的版本、啟動狀態及必要資料完整性結果，恢復服務與畫面，再記錄完成。表單恢復須綁定原帳戶，不能在切換帳戶後送出舊草稿。

暫停寫入、最後保護與切換必須連續受協調器管理。單獨讀取一次 coverage 不構成部署鎖；也不能把核心 HTTP 請求排空當成外部 AI 或發送程序已停止。

| 情況 | 行為 |
| --- | --- |
| 下載、驗證、空間或來源問題 | 保持現行版本，顯示原因，修正後重試準備 |
| 忙碌、未保存或暫停逾時 | 保留候選與工作；只有未切換元件且恢復已讀回時才延期重試，未知狀態保留待核對 |
| 同時點擊或網絡回應遺失 | 讀回同一 operation；不重建備份、不重複遷移或發送 |
| 新版啟動失敗且資料相容 | 完整設計目標是按已驗證路線復原；v2 未提供多元件自動回退，先保留資料與檢查點待核對 |
| schema 已變或已有新版寫入 | 保護新增資料，選擇相容修復或明確資料恢復；禁止直接覆蓋舊備份 |
| 多元件部分成功 | 保存真實版本組合與未完成步驟，回報 `recovery_required`；不自動重啟、恢復接收或報全部成功 |
| 發送或外部工作結果未知 | 查回原事件／工作；未釐清前不重新送出或重建工作 |

舊版及候選清理由保留政策管理，只處理已核實屬於該工作室的產物。仍有工作引用、恢復需求或未知操作時保留所需版本。

## 八 使用者介面

左下角入口在有適用更新或需要處理的狀態時提示，平時保持安靜。點開先顯示對工作有甚麼改善、影響哪項服務、是否需重新載入／短暫停頓，以及能否現在套用。版本與技術詳情放在展開區。

| 狀態 | 顯示與動作 |
| --- | --- |
| 尚在準備 | 正在背景準備，可繼續工作；可查看階段，不編造百分比 |
| 已準備 | 更新已準備好；查看內容、套用更新、稍後 |
| 等待工作 | 明確顯示哪項服務或未保存工作阻礙切換 |
| 正在套用 | 顯示目前階段；防止重複操作；保留操作查詢入口 |
| 已完成 | 顯示已更新元件及必要的重新載入提示 |
| 未完成 | 說明仍在使用的版本、受影響服務及可接續動作 |

不相關模組不通知，不因更新提示刷新公司資料。下載完成不代表已安裝；服務啟動不代表模型或渠道已接通。套用完成不自動改變自動回覆、人工接手或發送授權。

## 九 測試與客戶安裝核對

### 發布前在開發端完成

在本機及隔離候選環境驗證固定產物，包含乾淨安裝、支援的舊版升級、客製設定保留、資料遷移、故障及恢復。測試材料採合成資料；固定產物通過後原樣發布，不在客戶主機即場改程式或重新建置另一個包。

二號測試工作室可作經授權的候選驗證目標；若其承載真實客戶服務，另用隔離候選環境。測試成功不自動授權部署其他工作室，也不複製測試台的資料、登入及渠道連線給客戶。

### 客戶安裝只完成必要核對

只核對目標與權限、版本條件、檔案與來源、資料保護、可切換狀態、真正載入版本及啟動健康。資料變更按遷移合約核對完整性。現有有效備份證據可重用；不為每次普通更新重新跑開發測試或整套渠道驗收。

改變身份、資料格式、存取控制或接駁合約的更新仍有對應保護與讀回要求。首次平台／渠道接入需要的實測另列任務，不能因本功能安裝成功而冒稱通過。客戶環境超出已測支援組合時，先回開發端處理，不提供「可套用」的假象。

### 必需合成驗收情境

| 情境 | 通過條件 |
| --- | --- |
| 五個獨立工作室 | A 更新後 B 至 E 的版本、資料、憑證及服務保持不變 |
| 不同服務組合 | 只有安裝對應 AI 且有授權的工作室收到提示 |
| 背景準備及斷線 | 準備失敗不影響舊服務；同產物重試不重複建立套用工作 |
| runtime 與依賴 | 原始碼下載完成不能冒充就緒；套用時使用已準備的固定依賴，不改其他工作室的 runtime |
| 可信來源與撤回 | 損壞、未授權、簽章不符或撤回包不能套用 |
| 核心與模組相依 | 不相容組合被阻止；需要合併更新時顯示完整影響及執行次序 |
| 重複點擊與程序中斷 | 同一更新意圖不重複遷移，重新啟動後由真實狀態接續 |
| 多分頁及草稿 | 原帳戶可恢復，未保存內容不丟失、不跨帳戶提交 |
| 忙碌 AI 與人工接手 | 依安全邊界等待或處理；人工控制與權限變更仍生效 |
| 來訊與未知發送 | 不重播舊來訊、不重送未知訊息；暫存能力與中斷限制如實呈現 |
| 客製設定與私人模組 | 通用更新不覆寫客製值，不向其他客戶洩漏專用套件 |
| 跨資料域遷移 | 核心、客服與橋接各域有相符保護及恢復證據 |
| 部分成功與新版寫入 | 不假稱整體成功，不用舊備份覆蓋新增資料 |
| 未支援宿主 | 明確報告能力缺失，不退回建立新工作室或新 Agent |
| 客戶安裝副作用 | 安裝流程不建立測試對話、不發送驗收訊息、不啟用新業務權限 |

後續程式改動依各來源的 AGENTS、既有必要測試與 CI 執行；共用 harness 的收據綁定實際輸入與產物。文件交付只做文件、連結、能力描述與差異檢查，不以此宣稱功能通過。

## 十三 v2 來源實作現況與剩餘驗收

本批按「先回歸、版本依賴、客服獨立更新、備份去重、發行渠道」次序開發。以下是程式讀回可確認的能力；來源保存、最終固定候選檢查、PR／發布及客戶部署仍是分開的狀態。主流程仍在收集最終整批回歸與候選收據，不能以本節先行宣稱全部驗收完成。

| --- | --- | --- |
| 發行與版本依賴 | `installer_catalog.py` 驗證簽章目錄，解出有限明確版本的完整依賴組合、計劃摘要與有序發行清單；保留已安裝的無關元件 | 不因新目錄自動安裝另一個 AI；缺失、循環、未授權及不相容組合拒絕準備；不是跨程序交易 |
| 渠道與發行權限 | `test`／`stable`／`private`、元件／渠道受限公鑰、安裝身份 audience、序號防倒退、期限、撤回與套用前重驗 | 私人 audience 只控制目錄適用性；帶登入的私人下載、正式渠道托管及長期支援政策仍待完成；stable 拒絕預覽／候選 |

| 客服私人資料保護 | 正常停止核心後，隔離複製完整資料及 SQLite WAL、以 backup API 產生一致庫、完整性及隔離還原核對；保存固定設定和私人 ZIP 副本 | 不包含外部橋接資料／手機登入；相同覆蓋、24 小時內及副本雜湊相符才可重用；未知結果不覆寫 |
| 工作與未知結果 | BlueSAI 保存已知 runtime、prompt／政策、模型及知識證據；中斷工作不可悄悄換已知內容重跑，uncertain 發送不重送 | 不代表外部模型內部版本可固定，亦不啟用模型或重新授權；未收到的外部事件不冒稱已保存 |
| 部分成功 | 保留完成元件、實際觀察版本、登記結果及各資料域檢查點，回報 `recovery_required` | 未完成未知部分結果的自動復原／接續；重新 run 不盲目重啟，也不自動恢復接收或回退資料 |

核心目前 schema 8、客服 schema 7；v2 僅支援各元件升級前後 schema 不變。兩個數字不是共同資料庫，亦不表示已提供跨 schema 遷移。固定現有 Python 與操作者提供的 Node 都在準備階段核對，不修改系統 runtime。

接入與操作使用既有 `studio_installer.py init/run/status/check/apply`，新增 `module-add --node ... --config ...` 與 `channel-set --feed ... --channel ...`。發行者用 `package_managed_release.py build-component --requires-json ...` 建立指定客服包，並以 `package_release_catalog.py build/promote` 建立或提升簽章渠道。完整參數與一般化示例見[安裝器操作](MANAGED_INSTALLER.md)，不把本計劃當成私人部署操作單。
