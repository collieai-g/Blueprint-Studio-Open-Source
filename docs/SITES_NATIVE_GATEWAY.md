# Sites 入口與原生後台：資料可獨立備份及更新

本路線把 Sites 用作原版工作台及 MCP 的入口，將公司資料、附件、登入帳戶及備份保存於獨立原生後台。入口沒有 D1／R2 公司資料副本，所以更新公司後台不需要 Sites 的資料快照能力。

**目前提供接駁來源、單檔建置工具及隔離整合測試；不是已部署的網站，也不是舊 Sites 資料搬遷工具。** 使用者已選「另裝新站、保留舊站」時，只使用獨立的新服務、持久磁碟及 Site；原站不動。原 Sites 內已有 D1／R2 資料的更新繼續按 [UPDATE_ROUTE.md](UPDATE_ROUTE.md)，不能直接把本程式蓋上去當成完成升級。

## 安裝由 AI 依次完成

1. **先部署原生後台。** 使用包含 `GET /api/runtime` 的完整來源，按 [NATIVE_LIFECYCLE.md](NATIVE_LIFECYCLE.md) 部署原版 Python／Docker 服務，使用持久資料及備份目錄。核對 HTTPS、登入、備份下載、隔離還原、另一個私人耐久副本及原服務重啟。AI 工作區的臨時伺服器不能充當正式主機。
2. **再建立私人 Sites 入口。** 讀取目前官方 Sites 技能，使用受支援的 Worker ESM starter。保存平台回傳的精確 Site ID；`.openai/hosting.json` 宣告 `capabilities: ["mcp"]`，本路線不用的 `d1`／`r2` 保持 `null`，不可沿用舊站綁定。平台設定、進度及秘密存公開倉庫之外。
3. **產生單一 Worker。** 在公開來源 checkout 執行下列命令，輸出至私人建置位置，再放入 starter 的 `worker/index.js`。沿用官方 starter 的建置、驗證、來源保存及發佈流程，不自行猜平台封裝格式。

   ```sh
   python tools/build_sites_gateway.py --output /實際私人建置目錄/worker/index.js
   ```

   工具不覆寫已有檔案。再次建置先使用新的私人輸出目錄，再由 AI 核對差異後更新同一入口來源。產生的 Worker 不包含任何公司來源、資料、Site ID 或秘密。
4. **設定三個伺服器變數。** 使用 Sites 官方秘密設定入口，不能寫入前端、Git、聊天或命令參數。

   | 名稱 | 內容 |
   | --- | --- |
   | `BLUEPRINT_SITE_ORIGIN` | 此新 Site 的精確 HTTPS 根網址 |
   | `BLUEPRINT_BACKEND_ORIGIN` | 已驗證原生後台的 HTTPS 根網址，不能與入口相同 |
   | `BLUEPRINT_SITE_ACCOUNTS` | 平台使用者 ID → 原生帳戶的私人 JSON 對應表 |

   對應表格式如下，全部是占位值，並非可用帳密：

   ```json
   {
     "已核實的Site使用者ID": {
       "username": "已存在的後台帳戶",
       "password": "在安全入口設定的真實密碼",
       "read_only": false
     }
   }
   ```

   首次可先以空表 `{}` 發佈受保護入口，使用者在同一 Site 登入後開 `/_blueprint/identity` 取得自己的 Site 範圍 ID，AI 核對後設定對應表。未對應的使用者不能看公司內容。每位成員對應各自的後台帳戶；不要把所有訪客對應到老闆帳戶。停用成員時同時移除對應並停用原生帳戶。
5. **核對身份與能力。** `/_blueprint/status` 顯示入口版本、資料後台網址、API 合約及維護能力。這不是完整備份證據。登入後 `/api/info` 回報 `deployment_mode: sites_native`；左側 AI 按 [AI_CONNECT.md](../AI_CONNECT.md) 沿用 Sites 外掛登入並核對實際工具。確認權限較低的帳戶無法讀取完整備份或受限資料。
6. **完成真實讀寫。** 按 [CONNECT.md](CONNECT.md) 讓目前對話載入該 Site 的外掛，執行工具寫入及讀回；右側查回同一 ID。48 個工具共用原生 API，備份操作仍由原生後台核對擁有人。其他 AI 客戶端要另外核對 MCP／OAuth 相容性；不能複製平台 cookie。
7. **安裝時演練下一次更新。** 用明確標示的測試資料及附件，保存備份並隔離還原，再於所選主機重新部署已測試來源，核對同一資料、登入、畫面及 MCP。記下確實可執行的部署方式，才開始存正式公司資料。

畫面及靜態資產直接來自原生後台，保留原版內容。下載以串流轉送，不把完整附件 ZIP 載入 Worker 記憶體；平台本身的請求限制仍須實測，大型備份可由原生擁有人直接下載。瀏覽器偏好仍按原有方式另存；原生完整備份不包含 Sites 身份對應、平台秘密、來源或主機設定，這些另外私人保存。

## 之後更新甚麼

| 變更 | 操作 |
| --- | --- |
| 原版畫面、公司功能或原生資料格式 | 備份並核對原生資料，部署同一原生服務及持久磁碟，完成遷移及驗收。相容 API 下不需要重建 Sites。 |
| MCP 新增工具或 Sites 接駁程式 | 先部署相容後台，再建置並發佈同一 Sites 入口。平台刷新工具後，核對目前對話的工具與實際讀寫。 |
| 帳戶或權限 | 更新私人對應及原生帳戶，重新驗證受限角色；不重設資料庫。 |
| 未來模型或客服流程 | 按 [Agent 路線](AGENT_ROADMAP.md) 另行實作與驗收；安裝接駁層不代表已有客服執行器。 |

接駁版本 `1.0.0` 接受 API 合約 `blueprint-native/1` 及已啟用的原生維護。產品版本可以不同；資料 schema 的遷移及相容性由原生服務管理，相容 API 下不因內部資料版本改變而要求重新部署入口。如果將來 API 合約不相容，停止轉送並明確提示，不繼續猜測寫入。`/_blueprint/status` 與部署結果分開保存，不能把能力宣告當作備份、異地保存或工具驗收成功。

更新助手的接續資料會保留 `deployment_mode`、`backend_origin` 與 `gateway_version`。來源仍要分別保存原生後台與 Sites 接駁的已部署版本；瀏覽器匯出只提供接續線索，AI 必須再從服務讀回核實身份及實際儲存。

## 邊界與故障處理

- 這個模組**只能放在 Sites 驗證身份的入口之後**。它信任平台提供的 `oai-authenticated-user-id`；直接暴露到一般公網 Worker 會缺少身份驗證，不是受支援用法。
- 呼叫者不能指定另一個後台網址、帳密或角色。轉送只加入私人對應帳戶的授權，不傳送瀏覽器 cookie、平台 token 或來自使用者的身份標頭。
- 後台要求重新導向、登入失敗、合約不符或備份維護未啟用時停止。逾時不代表寫入未發生；先讀回，再決定是否重試。接駁程式不自動重送寫入。
- Sites 或原生主機暫時不可用時分開診斷。需要在 AI 執行環境直接存取原生網址時，按平台支援方式設定網絡；不能關閉 TLS 或繞過代理。
- 平台發佈、付費主機、異地儲存及實際 AI 客戶端授權仍是安裝工作。這個模組不會取得或假造這些能力。
