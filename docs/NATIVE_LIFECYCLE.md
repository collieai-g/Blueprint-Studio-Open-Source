# 首次安裝就準備好下一次更新

V2.5 的主要路線是原生 Python 本機／雲端後台。原版介面、公司功能及資料格式保留；新增完整備份、下載、還原演練、啟動前遷移檢查，以及中斷後的資料回復。以下操作由 AI 執行，使用者仍只需要首頁的「首次安裝」及「持續更新」兩段指令。

完成標誌是：**可以使用，也確實可以備份、取回、還原及再次部署。** 在 AI 暫存工作區啟動服務不能代替長期主機。Sites 的儲存與發佈方式不同，不能套用本頁工具或宣稱已取得相同能力。

如果使用者已選「全新安裝原生工作台，保留舊站不動」，先按 [任務選擇規則](INSTALL.md#先確定這次任務才讀取進度) 建立獨立服務與私人進度。舊 Sites 的完整備份、候選版本及封裝不作為新安裝前置條件；新站不自動取得舊資料。只有更新原站或明確搬遷資料，才需要處理該舊站的備份與搬遷。

## 安裝前先確認五件事

| 核對項目 | AI 要取得的實際結果 |
| --- | --- |
| 執行位置 | 使用者的電腦，或可持續運行、能停止及重新部署的原生雲端服務 |
| 私人儲存 | 資料與備份都有持久目錄；不在 Git checkout、映像暫存層或 AI 環境快照內 |
| 正式入口 | 本機 loopback；雲端有 HTTPS、原生登入及單一服務實例 |
| 備份取回 | 擁有人能經 API／瀏覽器下載完整 ZIP，另存私人耐久位置 |
| 下次更新 | 能取得固定版本、停止原服務、部署新程式並沿用原儲存與網址 |

缺少必要能力時，先選可用主機，不要等開始存公司資料後才發現無法備份。有 Sites 或網頁預覽，不代表上述五項已具備。使用者明確選擇其他平台時先說明及驗證，不暗中切換。

## 私人目錄從一開始分開

```text
公開程式/                  # 只放通用來源
私人安裝/
  data/                    # 公司資料庫、登入及原始附件
  data-backups/             # 自動備份、還原證據及 installation.json
  INSTALL_PROGRESS.md      # AI 記錄來源版本、啟停方式及驗收進度
```

新 Docker／Render／Railway 安裝把持久磁碟掛載在 `/data`，設定：

```text
BLUEPRINT_DATA_DIR=/data/library
BLUEPRINT_BACKUP_DIR=/data/backups
BLUEPRINT_BACKUP_INTERVAL=86400
```

預設備份間隔是 24 小時，允許 60 秒至 7 日；只在服務運行時執行。同一磁碟的備份不能抵禦整顆磁碟遺失，仍要下載一份到另一個私人耐久位置。備份不會自動刪除；空間不足會回報，更新前檢查不通過便停止。容量按實際資料及備份份數安排。

已有安裝若直接用 `/data` 存資料，**繼續用原路徑**，另選持久備份目錄或磁碟。新啟動器看到 `/data/access.json` 或舊資料庫時，會拒絕悄悄改用空白 `/data/library`。不要移除原 volume 或執行 `docker compose down -v`。

## 第一次安裝：由 AI 完成真實驗收

1. 取得最新正式 installer，核對 release、tag、commit 及下載雜湊，把版本寫入私人進度。保存所選來源；日後回復要使用相符版本。
2. 用 `setup` 準備公司資料，在全新的私人資料目錄執行一次 `library-init`。密碼只在安全環境或終端機提示輸入。已有內容但沒有登入設定時會拒絕初始化，先修復而非清空。
3. 用 `python blueprint.py library --data <私人資料目錄>` 或原生容器啟動。正式啟動器先取得資料目錄鎖，建立完整備份，還原到獨立目錄核對，再檢查遷移及啟動網站。備份或演練失敗時不會提前開放 HTTP。
4. 登入原版工作台，在「偏好設定 → 更新助手」查看完整備份狀態。擁有人可按「備份公司資料」及「下載完整私人備份」。ZIP 包含資料庫、登入設定和原始附件；瀏覽器排版另用「下載接續資料」保存。
5. 用與正式站相同版本的驗收工具，實際建立備份、下載、核對雜湊、還原副本，再以原帳戶登入還原副本：

   ```sh
   python tools/check_installation.py --url "https://你的正式後台網址" --output "/私人驗收/首次安裝"
   ```

   本機使用實際 `http://127.0.0.1:8787`。工具只讀取安全環境中的 `BLUEPRINT_BACKEND_USERNAME`、`BLUEPRINT_BACKEND_PASSWORD`，不把密碼放在參數。輸出必須是新的私人目錄，保留 ZIP、快照及 `verification.json`。正式工作資料不被覆寫。下載最大 8 GiB；更大的資料使用主機檔案備份路線。
6. 將已驗證備份另存到使用者確認的耐久私人位置，再讀取核對。AI 暫存目錄與真正異地保存分開回報；工具不會自動宣稱已完成異地備份。
7. 保存一筆使用者同意的工作及附件，停止並重新啟動原服務，查回相同 ID 與附件內容。最後按 [CONNECT.md](CONNECT.md) 驗證目前對話的 MCP 寫入／讀回及右側畫面。備份驗收不代替這兩項驗收。

單一實例是這條路線的前提。服務持有作業系統資料鎖；其他程序應使用 HTTP／MCP，不直接開資料庫。舊式 `workday-connect --data` 留給已停止服務的離線使用；運行時改用 `--url http://127.0.0.1:8787`。不要讓其他 SQLite 工具直接寫入正式資料。

## 每次更新：同一個入口、同一個服務

1. 讀 [UPDATE_AI.txt](../UPDATE_AI.txt)，固定本次正式 tag／commit。核對 `installation.json`、私人進度與自訂程式；已有候選就接續，不另建工作台。
2. 用擁有人維護工具建立新備份，下載到私人耐久位置並核對。也可用上方驗收工具，選本次全新的輸出目錄。舊正式版沒有維護 API 時，先按其受支援方法完整備份，不能要求先升級才取得必要備份。
3. 保存原來源版本、主機啟停方式、環境秘密的私人管理位置，以及原瀏覽器排版。更新前確認停止、啟動及回復的實際操作。
4. 測試新版，停止原服務／舊容器，改用已核對的程式，保留資料與備份掛載、登入及網址。由現有平台執行部署；本工具不會取得平台權限、購買主機或自行從 GitHub 執行未知程式。
5. 程式內容有變時，啟動器先備份及還原副本，在副本試行資料遷移，逐筆核對舊紀錄、原附件及登入，再對正式資料遷移及核對。期間尚未接收使用者請求。
6. 正式遷移失敗或更新中斷時，回復更新前資料，保留失敗副本於原資料目錄旁的 `.failed-…` 目錄，然後停止該份失敗程式。AI 讀私人 `installation.json`，選回原程式或已修復版本；**資料回復不等於程式部署已回復**。
7. 成功後核對正式版本、原紀錄、附件及登入，再驗證目前 AI 工具和同一筆畫面結果。相同程式重新啟動不重複遷移，也不會因重貼指令而重建資料。

成功使用新版後才降版，必須先保存新增資料，再還原與舊程式相符的備份。不能只換舊程式；啟動器會拒絕直接降低已記錄版本。遷移成功後發生的其他應用錯誤，由 AI 按實際情況回復，不能聲稱所有錯誤都會自動回滾。

## 不依賴雲端供應商的還原工具

停止服務後，備份原生資料：

```sh
python tools/upgrade_workspace.py snapshot --data "/私人資料/data" --output "/私人備份/本次更新" --service-stopped
python tools/upgrade_workspace.py check --snapshot "/私人備份/本次更新"
```

收到 ZIP 時，使用維護狀態或私人驗收紀錄提供的 SHA-256：

```sh
python tools/upgrade_workspace.py unpack --archive "/私人備份/backup.zip" --sha256 "已核對的64位雜湊" --output "/私人備份/解開快照"
python tools/upgrade_workspace.py restore --snapshot "/私人備份/解開快照" --output "/私人資料/還原演練"
```

`restore` 只接受不存在的新目錄，絕不直接蓋過正式資料。先用相符版本，在另一個 loopback port 啟動副本核對登入及內容。真的要回復時，停止原服務、保存目前資料，再讓原服務使用已驗證的還原目錄，保留網址與存取限制。所有路徑由 AI 換成核實過的位置。

## AI 維護工具與真實狀態

原生 MCP 在原有 30 個共通工具外，新增 `blueprint_backup_status`、`blueprint_backup_create`，共 32 個。維護工具只供擁有人使用；唯讀連接不提供建立備份。建立操作只排入工作，須再查狀態看到新的、通過還原驗證的備份 ID。下載仍需擁有人登入，內容不能放入模型對話或公開倉庫。

Sites 保留原有 30 個共通工具；原生維護工具不能備份 Sites 的 D1／R2。平台沒有可驗證的備份、還原及部署路線時，列為待適配，不能稱為完整安裝。聯絡平台支援是查明缺口的選項，不是每次更新的固定操作。

分別記錄：程式版本、備份及還原、異地副本、正式部署、重啟保存、AI 讀寫與介面核對。ZIP 不包含平台帳戶、TLS、環境秘密、原始碼或瀏覽器排版；這些仍按各自私人設定及來源流程保存。
