# 安裝與更新：只做仍然需要的步驟

這是首次安裝、原站更新與開源發行共用的流程定義。文字入口只選擇任務，平台細節沿用[安裝指南](INSTALL.md)、[更新路線](UPDATE_ROUTE.md)及[原生生命週期](NATIVE_LIFECYCLE.md)。先讀已保存的選擇和證據；不要重新詢問已有答案。

開源來源修改的重現、元件分流及 PR 步驟見[開發指南](DEVELOPMENT.md)；相關[驗收](DEVELOPMENT_ACCEPTANCE.md)與[私隱規則](PRIVACY.md)沿用本頁的 `source_release` 任務，不另建安裝流程。

## 先按任務減少工作

| 任務 | 必須完成 | 不需要執行 |
| --- | --- | --- |
| 開源來源發行 | 通用來源、文件、必要測試及可審閱 PR | 私人站備份、正式資料寫入、私人服務部署 |
| 日常資料保存 | 原有授權、版本檢查及同 ID 讀回 | 安裝、Git 提交及部署 |
| 相容套件登記 | 固定來源、合約與設定預檢、登記及讀回 | 重寫宿主、空提交或宿主部署 |
| UI 變更 | 受影響介面、可及性、資產及原資料唯讀核對 | 無關模型、渠道及固定重啟全套驗收 |
| 新持久層 | 權限、CAS、重試、回復、一次實際 AI 讀寫與必要重啟 | 每個入口各新增一筆驗收資料 |
| schema／身份遷移 | 當前一致完整備份、可讀私人副本、遷移及回復測試、舊資料和附件核對 | 不能刪減這些核心保護 |
| 獨立新安裝並保留舊站 | 新服務、新資料及備份位置、自己的完整驗收 | 舊站的備份、候選回收及重新部署 |

使用 `tools/lifecycle_plan.py --help` 產生版本化計劃和檢查適用範圍；[機器合約](LIFECYCLE_API.md)說明輸入 tree、驗證收據與靜態套件預檢。它不執行部署，也不把輸入的證據自行認定為正式驗收。來源發行只在本機／CI 產生通用計劃及檢查收據，不為記錄進度連接或寫入私人工作台；維護 API 的來源發行例子只是合成合約示例。

## 同一計劃從未完成階段續行

```text
discover → plan → backup_gate → apply → publish_if_needed → verify → complete
                                             ↘ waiting_user → 原未完成階段
```

[原生維護 API](MAINTENANCE_API.md) 保存 owner-only 工作紀錄，使用固定 `operation_id`、`plan_digest` 及 `expected_version`。同一寫入重試返回原結果；不同計劃不能覆寫原紀錄。結果不明先讀回，不重新建立備份、分支、卡片或部署。`waiting_user` 保存具體缺項及接續階段；只有本人登入、授權或平台操作交給使用者。已成功發佈但人工驗收未完成，要分開回報。

來源證據分別保存 upstream commit、adapter 版本、私人來源 commit、平台來源 commit、artifact SHA256 與 saved version。平台序號不是產品版本；commit 留在私人工作紀錄，避免將提交雜湊寫回自己的來源造成循環提交。私人來源、站點設定、備份、聊天及工作紀錄都不放公開倉庫。

## 備份保護與下載分開核對

`GET /api/maintenance` 的 coverage 在一致讀取中涵蓋資料正文、歷史、登入／權限、schema 及附件內容；記錄數量相同不能代替指紋。維護收據不參與業務 coverage，避免每寫一張收據又需要備份。

相同 operation 的備份請求沿用同 ID，不重新打包或重做隔離還原。是否可以保護下一次變更，另外核對同服務、相同 coverage、相容 schema、檔案完整、有效還原證據及仍可讀的私人副本。正式部署或遷移前重查 coverage；其他使用者寫入後不能憑「今天備份過」放行。重試返回舊 ID 不代表它仍覆蓋目前資料。

三項證據各自呈現：平台檔案完整、隔離還原成功、客戶端私人副本已核對。客戶端必須實際讀取檔案，核對大小和 SHA256，再提交私人檔案引用及讀回收據；伺服器保存的是客戶端陳述，不會因此聲稱能讀取私人儲存。同平台備份亦不等於異地耐久副本。

工具取得的同源下載入口仍需擁有人身份；不發放公開 URL，不把登入或 bypass token 交給 shell。只能使用瀏覽器時，先掛下載事件再點一次，取得真實檔案後核對。中斷只補同 ID 的缺失下載。部署後比較使用唯讀 coverage 及原附件清單，不為比較重建完整 ZIP；成果快照按里程碑及保留政策另外建立。

## 瀏覽器排版接續檔按需要保存

後台已同步的個人版面包含在完整資料備份內。瀏覽器仍可能有未同步修改、舊版原始備份及本機顯示設定。由目前登入瀏覽器計算 origin、帳戶範圍、格式版本及偏好 SHA256；後台不能直接讀取 localStorage。

只有排版遷移、首次保護自訂內容或跨環境接續才匯出正文。相同帳戶和雜湊的有效私人副本可以沿用。純後台或日常資料操作無需下載。點擊下載不能代表私人副本已核對。新版匯出檔及本機收據按帳戶隔離；有 `account_scope` 的檔案只能由同一帳戶還原。舊 `blueprint-update-handoff` 格式仍可手動匯入；無身份範圍的舊檔不能當作帳戶已驗證副本。接續檔不是 AI 連接指南或完整公司資料備份。

## 分工凍結後才正式驗證

分工各自驗證所屬變更，主線待來源凍結後 build 並執行一次正式回歸。檢查收據綁定實際輸入 tree、命令及產物雜湊；只有相關輸入未變才可重用。不可用舊版本通過結果證明新輸入已驗證。只停止自己建立的 session 或 PID，不按寬泛程序名稱中止其他測試。

保留當前 Sites 官方來源 helper 的開啟、打包、推送及精確 saved version 發佈規則；GitHub 推送不等於私人服務部署。能力缺失經確認後記為 unavailable 或 waiting_user，不重複嘗試本人尚未送出的交接，也不把 pinch scale 當作桌面 200% zoom。沒有經實測的分鐘數承諾。
