# 減少更新時的手動操作

先按 [完整更新路線](UPDATE_ROUTE.md) 執行到原站可用。來源保存只是階段 1 的交接方式；已有可讀檢查點後，繼續備份、原站部署、右側驗證及 AI 接駁，不能以「已保存候選」結束整個升級。主分支指南會修正操作路線，程式仍固定使用已選的正式 tag／commit。

把 [UPDATE_AI.txt](../UPDATE_AI.txt) 貼給有工具的 AI。已安裝更新助手的工作台亦可在「設定 → 更新助手」複製指令；網址與現有版本會自動填入，排版會在原瀏覽器另存。舊工作台沒有此入口時，直接使用文字入口，由 AI 處理。

2.4.1 提供可執行的來源保存、環境檢查、原生資料備份及接續包工具。它減少重複查找、填寫和換對話後重做的工作。**它不是網站自我部署服務**：平台登入、帳戶授權及環境設定仍使用平台支援方式；Sites 的完整後台適配、正式備份與發佈仍由具備該平台工具的 AI 完成。不要把「複製指令」或「產生接續包」顯示為更新成功。

2.4.2 另加 [私人來源檢查點](SOURCE_CHECKPOINT.md)。本機 ZIP 不等於已交接：換環境前把已檢查的候選來源保存到另外核實的私人倉庫，再按確切 commit 下載核對。公開開源倉庫不得保存私人工作台來源、資料、聊天、設定或接續包；資料庫、附件與登入備份不放入來源檢查點。

## AI 的執行順序

1. **沿用已有進度。** 找私人安裝紀錄、原 Site ID／服務／資料位置、既有候選來源及上一份接續包，核對是否仍對應原正式站。不要重新問使用者已有答案，也不要丟棄已通過本機測試的候選版本。
2. **先核對工具及環境。** 收集實際工具清單、原網站、目前環境狀態和可用備份／發佈途徑。平台外掛能否使用與執行環境能否直接 HTTP 是兩個獨立檢查；其中一路受阻不等於另一路也受阻。先完成可用路線的工作。
3. **保存來源和資料。** 候選準備好或即將換環境時，按 [SOURCE_CHECKPOINT.md](SOURCE_CHECKPOINT.md) 保存並讀回私人遠端檢查點，記錄確切 commit。 使用下列工具建立私人接續目錄；完整備份仍按 [UPGRADE.md](UPGRADE.md)。瀏覽器資料、原始碼、資料庫和附件分別核對。
4. **整合及發佈至原服務。** 選定確切正式 tag／commit。私人改動保留及整合，不能以 ZIP 直接覆蓋整個專案。已經有 Sites 候選版本就先核對並沿用；UI 包仍不是完整 Sites 後台。
5. **正式驗收。** 同一正式 origin、版本、原紀錄與附件、登入、真正保存／讀回、右側顯示及重啟保存分別列證據。由左側按 [AI_CONNECT.md](../AI_CONNECT.md) 核對目前實際能力，能控制同站登入分頁時優先驗證畫面操作；MCP 可選，選用時另列目前工具載入（共通 40 個，原生及 gateway 42 個）及真正 blueprint_verify_connection 的證據。客戶端產生 32 位十六進位 challenge、實際 client 及有效 date，保留相同紀錄編號與重試參數，不等待右側精靈，也不能用 HTTP／畫面偽造 MCP 通過。本機測試不能替代正式驗收。

V2.7.4 畫面核對以四個主入口與「設定」為準。新總覽預設只有標題與排版入口；其他卡片可從編輯器加入，從舊版升級時也先只顯示標題，原有模組位置及資料保留；新版可見內容由使用者勾選並保存。AI 設定在左側按 AI_CONNECT.md 執行，不要求右側預設顯示說明圖或接駁精靈。

只有使用者本人才能做的登入／授權／平台操作才交給使用者，並交代目前的一個動作及成功標誌。遇到同一卡點先比較新舊證據，不重複要求相同操作。

## 由 AI 執行的工具

以下路徑由 AI 替換成已核對的私人位置；使用者不需要逐條輸入。工具使用 Python 3.10+ 標準庫及 Git，不連線、不部署、不初始化資料，也不改寫原工作台。新工具需先從已選版本取得，舊 checkout 未必已有。

### 保存原來源

```sh
python tools/update_assistant.py prepare \
  --project "/原工作台來源" --output "/私人更新/本次更新" \
  --url "https://原工作台網址"
```

有瀏覽器下載的 `blueprint-update-handoff.json` 時可改用 `--handoff "/私人位置/blueprint-update-handoff.json"`，不必再填網址。兩者都填時必須同站。

工具讀取原專案 `.openai/hosting.json` 的 `project_id` 辨認 Sites，否則以 `blueprint.py` 辨認原生來源；未辨認時保持 `unknown`，由 AI 查原部署設定。已核對 Sites 工具的 ID 但來源沒有 hosting.json 時，可用 `--site-id` 逐字傳入；不能猜 ID。平台內的版本序號不是程式版本。

私人目錄包括 `job.json`、原 Git 歷史、當前來源 ZIP（包含未提交及未忽略的新增檔案）及來源校驗碼。有未提交改動亦會保存，不能因此覆蓋自訂內容。Git 忽略的檔案、子模組、平台秘密及外部資料不在來源快照內；另按原部署方式備份。工具拒絕明顯的資料庫、登入檔及 `.env` 來源混入。完整 Git 歷史可能包含私人內容，接續包不可提交至公開倉庫。

重複 `prepare` 同一目標會沿用原紀錄，不覆寫初始來源。換不同網址或 Site ID 會停止。準備途中失敗的目錄只保留供診斷，沒有 `job.json` 就不能當作完成；修正原因後使用新目錄。

### 一次核對環境與工具

AI 以**本次**工具結果組成私人 `observations.json`，不要要求使用者手工寫 JSON：

```json
{
  "environment": {},
  "tools": [],
  "site": {"id": "平台回傳的原 Site ID", "current_live_url": "https://原工作台網址"},
  "publisher": {"available": false}
}
```

- `environment`：管理式雲端使用目前 `environment_status` 的結構化結果。保留 `observations_current`、`source_config_version_id` 及 `network_policy`。不要用草稿或啟動時的舊快照代替。目前環境不支援這個工具時留空，結果是「未知」，AI 依實際客戶端另行核對。
- `tools`：目前對話實際可呼叫的名稱陣列。接受原工具名或以 `__工具名` 結尾的平台名稱。0 個、部分舊工具、完整 40 個共用工具（原生另有 2 個維護工具）是不同狀況；工具載入並不證明讀寫成功。
- `site`：只選取平台回傳的 ID 及網址；不要把 `get_site` 整份結果寫到檔案，可能含短期憑證。
- `publisher.available`：AI 按目前 Sites 技能與可用工具核對後才填 true。它是能力回報，不是部署證據。缺少某個舊腳本時先找目前支援流程，不能杜撰替代發佈 API。
- 可選 `expected_config_version`：只有已取得使用者新發佈設定的真實版本 ID 才填；不能猜。與執行環境版本不一致時，工具明確回報「未套用」，不再要求重複加入網域。

```sh
python tools/update_assistant.py check \
  --job "/私人更新/本次更新" --observations "/私人更新/observations.json"
```

`checks.json` 只保存選取的診斷，原始平台回應不複製到接續目錄。網絡政策只有目前觀察有效、狀態 `enforced` 且完整清單包含網域，才回報政策允許；仍需實際連線及登入。整體永遠保持 `production_status=not_verified`，不能以觀察 JSON 冒充部署完成。

### 原生資料備份

AI 先停止原服務與所有寫入者，再執行：

```sh
python tools/update_assistant.py snapshot \
  --job "/私人更新/本次更新" --data "/原資料目錄" --service-stopped
```

自動沿用接續目錄，保存 SQLite 一致快照、登入及附件；不重複覆寫。`--service-stopped` 是操作者確認，工具不會自動停止服務。升級後使用既有工具逐列核對：

```sh
python tools/upgrade_workspace.py verify \
  --data "/原資料目錄" --snapshot "/私人更新/本次更新/database-before"
```

Sites 不使用這個本機備份指令。由平台保存原資料庫、R2／物件附件及必要設定，取得清單、完整內容與可還原證據；空資料表不能證明附件儲存也是空的。無可用完整備份途徑時，保留候選版本並說明具體缺少的能力，不能聲稱已備份。

### 私人完整封裝（仍須另行交接）

```sh
python tools/update_assistant.py pack \
  --job "/私人更新/本次更新" --output "/私人更新/blueprint-resume.zip"
```

`pack` 回報 `cross_environment_ready=false`，因為它只產生目前環境的檔案，沒有傳輸。不能要求使用者換環境後才發現 ZIP 取不到；先完成私人儲存與取回驗證。來源使用上述檢查點，完整資料包使用原平台或另外的私人備份位置，不能上傳公開倉庫。

`pack` 會再保存目前最新來源（包含未提交改動），保留原基準、每次來源檢查點、已放入目錄的私人備份與紀錄，並產生完整 SHA-256 清單。AI 可在這個私人目錄維護 `INSTALL_PROGRESS.md`、正式測試結果及備份，但不要放入短期 token 或原始聊天。大型資料備份可保留原平台的私人備份位置，不能假裝已包含進 ZIP。容量上限 128 MiB；此包可能含登入設定、附件及私人來源，不可公開。

早期 AI 手工建立的接續包可能使用其他清單格式。先讀其中 INSTALL_PROGRESS.md 並按原 SHA-256 清單校驗、取回既有候選來源，再用 prepare 納入新助手；不要因格式不同而丟棄成果或重做後台。

新環境取得本工具產生的接續包後：

```sh
python tools/update_assistant.py unpack \
  --archive "/私人更新/blueprint-resume.zip" --output "/私人接續/本次更新"
```

工具先檢查清單、每個檔案雜湊與路徑，再解到全新私人目錄；不覆蓋已有目錄、不執行包內程式。雜湊是傳輸完整性檢查，不是發行者簽章，只使用自己保存或受信來源的私人包。

AI 讀 `resume-manifest.json` 的最新 `checkpoint`，以其中 Git bundle 在新私人目錄建立來源，核對 `source.json` 的 commit。`working-tree.zip` 是當時完整的非忽略工作樹，包含未提交修改和刪除效果；先列出差異，再於隔離 checkout 恢復這份工作樹，不直接覆蓋正在服務的來源。原目錄的絕對路徑只是紀錄，不能假設新環境仍存在；下次封裝可用 `--project "/新私人來源"`。有 hosting.json 的 Sites 仍必須核對同一 Site ID。

先重讀本次環境與工具狀態，再接續未完成步驟。新環境不會繼承舊對話的工具載入或短期登入狀態。

## 能減少哪些操作

| 以往需要重做 | 現在由工具／AI 處理 |
| --- | --- |
| 重填網址、版本及安裝方式 | 更新助手讀取原網站；AI 核對原來源與 Site ID |
| 手工複製瀏覽器排版 | 自動私人保存，下載／同站還原 |
| 換對話後重新找候選程式 | 另外的私人倉庫來源檢查點，下載驗證後按確切 commit 接續；私人進度與資料備份另存 |
| 反覆加入網域或重新安裝外掛 | 分開辨認設定未套用、工具未載入、舊工具清單及正式版本 |
| 原生備份要重新組路徑 | 接續目錄內統一 snapshot 與原資料保留驗證 |

仍未提供：通用 Sites 後台、全自動 R2 備份、跨平台自動授權、排程更新或一鍵自行部署。這些需要對應平台支援與獨立實作；不能靠增加一段提示詞就承諾完成。

## 維護者發佈新版

更新 `blueprint_folders/__init__.py` 的正式版本號、相關版本參照及 `docs/RELEASE.md`，提交至主分支。GitHub Actions 在全部檢查通過後，以同一提交建立新 tag、完整 installer.zip 及 workbench.zip；已存在的 release 保留，不覆寫下載。亦保留既有 tag 觸發方式。這自動化的是開源版本的發佈，私人工作台不會因此自行部署。
