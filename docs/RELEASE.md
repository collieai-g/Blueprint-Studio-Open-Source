# V2.8.1：跨分頁、裝置及 Codex 的個人版面同步

修正卡片排版及顯示文字只保存於單一瀏覽器的限制。同一工作室、同一登入帳戶可共用總覽、每頁版面與來源引用；可見網頁約每兩秒只檢查版面更新。正在編輯時保留手上內容，離線保留待送修改，同欄位衝突須明確處理。

新增 `blueprint_get_presentation` 及 `blueprint_update_presentation`，讓 Codex 以相同身份、文件版本及讀回規則修改排版。公司資料不因版面同步而整頁重新載入，顯示文字亦不改寫原紀錄。

產品版本為 **2.8.1**，資料格式維持 **schema 7**；版面存於既有帳戶偏好的保留欄位，原有資料及本機備份保留。共通 MCP 工具為 42 個，原生／Sites 原生接駁另有兩個備份工具，共 44 個。

需要同時更新相容後台、介面與受影響的工具目錄。純 Sites 須把提供的版面適配模組接到原身份及正式儲存；不支援時明確顯示本機保存。GitHub 提交及本機驗收不代表任何私人工作室已更新。完整合約、遷移及驗收見[版面同步](PRESENTATION_SYNC.md)及[升級指南](UPGRADE.md)。

以下保留 2.8.0 的整合功能說明。

## V2.8.0：獨立外部服務的資料與指令介面

原生後台新增 **Blueprint Integration Contract 1.0**，讓獨立服務以受控 API 保存公司紀錄、接收操作指示及回報實際結果。產品版本 2.8.0、資料格式 schema 7、整合合約 1.0 及既有 `blueprint-agent/1` 分開管理。

- 每個私人資料目錄代表一家公司。外部服務使用綁定整合實例的專用憑證，伺服器只保存雜湊，並檢查資料種類、動作及選定資源的授權；憑證可以撤銷。
- 保存通用對話、訊息、工作、成果、註記及狀態證據，保留來源 ID、版本、時間及修訂歷史。同一鍵重試讀回原結果，不同內容不能覆寫。
- 操作指示先保存為 `pending`；外部服務回報後，才顯示已接收、執行中、完成、拒絕、過期、失敗或結果不明。結果不明不會自動重新發送。
- 增量事件以持久游標續讀；游標綁定整合及不可變事件錨點，資料缺口、備份還原或分歧需要明確重新核對。
- 已註冊服務在「工作 → 外部工作」呈現真實紀錄與指令結果；保留四個主入口、手動更新習慣及未保存草稿，不新增右側接駁精靈。
- 提供 [OpenAPI、JSON Schema 及共同樣本](../contracts/integration-v1/openapi.json)、[接入指南](INTEGRATION_GUIDE.md) 與虛構資料模擬服務。現有 `connected_client` 工作、HTTP／MCP 名稱及公司資料保持相容。

schema 7 是原生後台的新增資料表遷移。更新前沿用完整備份、隔離還原及啟動前演練；不能只替換介面，也不能讓 schema 6 舊程式直接開啟新版資料。回復前先保存升級後資料，再使用匹配舊程式的完整升級前備份。詳見 [升級指南](UPGRADE.md) 及 [原生生命週期](NATIVE_LIFECYCLE.md)。

這份來源變更不代表任何私人服務已部署或客服帳戶已接通。Sites 自身後台需要另行適配；既有介面適配器只有宣告相應能力後才顯示外部工作。WhatsApp、DOT、模型推理、客服期限及實際發送繼續由各獨立服務負責。

介面現以左側四個主入口配合頂部區域分頁，移除收窄側欄與路徑說明，搜尋、更新和手動新增集中到「操作」。每頁可獨立調整版面及顯示文字；工作與 AI 卡片可選放到總覽，總覽重新讀取目前獲授權來源。保留舊排版與原始備份，個人文字及來源選擇按帳戶隔離。
