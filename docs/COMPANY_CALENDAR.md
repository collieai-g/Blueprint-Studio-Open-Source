# 公司日曆：出勤、工作紀錄與待辦

[使用指南](USER_GUIDE.md) · [介面方向](COMPANY_INTERFACE_PLAN.md) · [原生更新與備份](NATIVE_LIFECYCLE.md)

「工作 → 日曆」用月份看公司運作，選日期查看當日詳情。它沿用四個主入口及原有白灰視覺，不要求公司先建立複雜的人事或排班制度。新功能屬於原生後台 `blueprint-calendar/1`，資料庫版本為 8。

## 使用方式

管理員先在日曆建立員工，可填姓名、僱用類型及部門。全職、兼職、合約、臨時及其他是業務分類，與老闆、管理員、一般成員的登入權限分開。可以先建立未有登入帳戶的員工，再由管理員綁定既有帳戶；建立員工不會建立登入或授予權限。已綁定帳戶不能改派另一人，以免另一人取得過往的私人紀錄。

月份格只顯示出勤、工作紀錄和待辦等數量；選日期後查看實際清單。管理員可按員工及僱用類型篩選，方便不同規模的團隊。沒有符合條件的紀錄會顯示空狀態；讀取失敗會顯示錯誤，不能當成沒有工作。

登入者在綁定本人員工資料後，可明確按「上班」及「下班」。後台以服務端時間保存，同一人只容許一段未結束時段；日曆所選的其他員工不會改變這個打卡對象。未有登入的員工可由管理員補登實際時段，須填原因。更正也須填原因，保留舊值、操作者和版本。

工作紀錄描述某日完成的工作，可記錄投入分鐘；公司待辦有日期、負責員工和完成狀態。沒有日期的日曆待辦在「未排期」保留。既有專案和待辦的期限，以及原有每日工作紀錄，也可在日曆開啟原項目；沿用原 ID、權限和保存方式。舊有自由文字負責人不會被猜測成新員工身份，因此按指定員工篩選時不混入這些未指派的舊資料。

## 日期與權限

| 內容 | 日期含義 | 可讀範圍 |
| --- | --- | --- |
| 出勤時段 | UTC 儲存，按公司時區顯示；跨午夜時在相關日期呈現同一時段 | 本人及管理員 |
| 員工工作紀錄 | 成果所屬日期；分鐘不等於打卡時間 | 本人及管理員 |
| 新公司待辦 | 全天期限，可未排期 | 本人獲指派的待辦、未指派的公司待辦及管理員 |
| 既有專案／待辦 | 原紀錄的期限，不轉成凌晨會議 | 沿用原有權限 |
| 既有每日工作紀錄 | 原紀錄所屬日期，不推斷員工或班次 | 沿用原有權限 |

公司時區預設為 `Asia/Hong_Kong`，可由管理員改成有效的 IANA 時區。日期型期限不因時區而改日；出勤仍保留原 UTC 時間及記錄時的時區。查詢和每日統計先套用後台權限，再按完整月份範圍取得資料，不只使用原清單第一頁。

一般成員不能從日曆讀到其他員工的人事、出勤和工作紀錄，也不能靠更改網址取得權限。管理員負責建立員工及分派公司待辦；一般成員可記錄自己的工作並完成分派給自己的待辦。新紀錄沒有刪除捷徑，避免抹去出勤或更正歷史；停用員工會保留原資料。

沒有打卡表示「未有紀錄」，不表示缺勤；時段長度與工作紀錄分鐘不直接用作薪資、加班或可付工時計算。首版未加入排班、假期審批、薪酬、定位、人臉辨識、外部日曆同步及背景監測。

## 保存與左右協作

所有公司資料透過已登入後台保存，不以瀏覽器儲存模擬成功。寫入使用版本檢查，衝突保留表單內容；建立及打卡重試沿用同一識別碼，結果不明時先讀回。切回視窗和閒置不輪詢公司資料，更新資料是明確操作；切月份、選日期及篩選亦會讀取對應範圍。

原生 MCP 額外提供日曆資料、月份及工作紀錄／待辦建立與更新工具，讓左側目前的 AI 讀取已授權內容、整理工作並保存到同一日曆。工具不會自動替員工上下班，也沒有新增模型或背景執行器。讀回相同 ID 與版本後才可回報已保存。

## 更新與適配

schema 8 以新增資料表保存員工、時段、日曆紀錄、重試識別碼及歷史；不回填舊人事工時為打卡，不改動既有來源 ID。原生完整資料庫備份包括新表。更新已有工作台前，依原生生命週期完成完整備份、隔離還原及遷移演練，保留原附件、登入與資料目錄。回復舊程式前先另存目前資料，再還原匹配舊程式的完整快照，不能降低 `PRAGMA user_version`。

Sites 入口連接原生後台時，可透過原有授權接駁取得此能力。純 Sites D1／R2 後台須實作同一資料、身份、版本及歷史合約，並在能力宣告包含 `company_calendar` 後才算支援；單換前端檔案不會建立持久日曆。未支援時顯示明確說明，不能落到私人資料的本機假保存。

原生 HTTP 入口在 `/api/studio/calendar/`：`meta`、`month`、`settings`、`employees`、`entries`、`attendance` 及 `history`。請以 [calendar_http.py](../blueprint_library/calendar_http.py) 的已驗證欄位及 [calendar.py](../blueprint_library/calendar.py) 的權限為準；這些路徑共用原有登入、同源寫入保護與錯誤處理。
