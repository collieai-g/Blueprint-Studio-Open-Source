# 帳戶版面同步

[返回首頁](../README.md) · [版面操作](LAYOUT.md) · [公司 API](STUDIO_API.md) · [更新](UPGRADE.md)

V2.8.1 將卡片位置、大小、收合、可見項目、顯示文字及總覽來源引用保存到目前登入帳戶。Codex、同一工作室的其他分頁及其他裝置使用同一份版本化設定。每頁有自己的配置；公司紀錄、文件原文和表單草稿仍按各自原有流程保存。

## 使用者會看到甚麼

在「調整版面」操作後，瀏覽器先保留本機修改，再送到相容後台。其他可見網頁約每兩秒檢查版面更新，網絡及背景分頁會影響實際延遲。已成功保存的版面可在同一工作室、同一帳戶的另一個瀏覽器讀回；不同帳戶不共用個人標題或排列。

正在拖動卡片、編輯版面或填寫欄位時，網頁保留手上內容，待完成編輯後才套用遠端變更。版面更新沿用原來的表單節點，不重建公司頁面或清空輸入。手機閱讀的臨時排列不會覆寫桌面大小。

兩邊修改不同欄位時可整合；相同欄位有不同改動時保留本機修改並顯示衝突，讓使用者明確選擇採用遠端版本或保存本機版本。斷線時顯示尚未同步，保留待送修改；不能把「已在本機保存」當作其他裝置已收到。登入失效或權限不足時先恢復登入，不能反覆以舊身份寫入。

同步只讀取版面設定。文件、工作紀錄、Agent 結果等公司內容仍在開啟頁面、成功保存或按「操作 → 更新資料」時重新讀取。網站不會因此監聽 Codex 對話或自動執行 Agent。

## HTTP 合約

使用原有已驗證身份及同源寫入規則。帳戶由伺服器推導，請求不能指定另一個 username、角色或公司。`/api/studio/state` 的 `capabilities.presentation_sync: true` 表示後台已提供此功能。

瀏覽器另外傳送 `X-Blueprint-Account: encodeURIComponent(username)`，比對啟動時看到的帳戶。這個可選標頭只是身份一致性檢查，不能用來選擇帳戶或取代登入。若另一分頁登入了其他帳戶，標頭與目前驗證身份不同時回傳 403，舊分頁不會把舊帳戶的排版草稿讀寫到新帳戶；重新載入及登入後才接續。

| 方法 | 用途 |
| --- | --- |
| GET `/api/studio/presentation` | 讀取目前帳戶全部版面文件及各文件版本 |
| GET `/api/studio/presentation?key=overview` | 只讀指定文件；不存在時 `documents` 沒有該鍵 |
| GET `/api/studio/presentation?since_version=N` | 聚合版本未變時回傳 `{version:N, unchanged:true}`，否則回傳完整快照 |
| PATCH `/api/studio/presentation` | 以 `{key, expected_version, data}` 原子比對並替換一份文件 |

不接受未知或重複查詢參數。`key` 與 `since_version` 同時提供時仍回傳所選文件，不能把完整集合的「未變」回應套在局部讀取。

完整快照格式：

```json
{
  "version": 7,
  "documents": {
    "overview": {
      "version": 3,
      "data": {
        "version": 1,
        "layoutVersion": 4,
        "texts": {"heading": "我的工作總覽"}
      }
    }
  }
}
```

最外層 `version` 是帳戶版面集合版本，供檢查更新。文件內的 `version` 才是 PATCH 的 `expected_version`；新文件使用 0。成功 PATCH 回傳同樣的 envelope，但 `documents` **只有這次寫入的文件**，不是完整集合，客戶端不得清空其他文件或據此略過未讀的其他變更。相同內容及正確版本的寫入不新增版本。

瀏覽器約每 15 次版面檢查取得一次完整快照，亦在重試時完整讀取，以核對版本與實際內容。發現聚合／文件版本倒退、已知文件消失，或相同文件版本卻有不同內容時，停止自動同步並保留待送修改。這可能是後台還原備份後的分歧；按「重新核對版面版本」取得目前快照，再對仍未保存的修改明確選擇保留內容，不能把舊草稿自動重播到已還原資料。

版本不符回傳 409，不能盲目以新版本重送整份舊資料。先讀回，保留原本草稿，以先前讀取的內容比較本機及遠端改動，再整合或交由使用者決定。PATCH 是整份文件替換，沒有伺服器端欄位合併；省略欄位會移除原設定。`data: {}` 可還原該文件的介面預設值，同樣需要正確版本。

## 文件內容及限制

| key | 可保存內容 |
| --- | --- |
| `overview` | 既有 `version:1`、`layoutVersion:4` 格式；`pages`、`columns`、`mode`、`visible`、`cards` 及 `texts` |
| `page:<route>` | 個別頁面，沿用實際路由；`version:1`、`active`、`pages`、`columns`、`cards` |
| `pins` | `{version:1, refs:[...]}`；只保存支援的原紀錄引用或模組路由 |

欄位可省略，渲染時補上預設值。不提供 HTML 或程式執行能力，不接受憑證或公司紀錄快照。顯示文字一律以純文字套用；`texts` 只接受總覽的 `heading`、`description`、`date`。

每帳戶最多 256 份文件、合共 512 KiB；每份文件最多 128 KiB。總覽最多 40 個卡片設定，每頁最多 200 個，總覽引用最多 24 項。顯示文字上限為總覽每欄 2,000 字元、各頁每項 4,000 字元。

儲存座標使用 24px 方格：頁數 1–3、欄數 6–96、x 0–95、y 0–143、寬 1–96、高 1–48。各卡片實際最小尺寸、碰撞及畫布邊界仍由既有排版引擎檢查；不能用 API 繞過可用版面規則。

`pins` 的來源為 `studio_record`、`agent`、`agent_job`、`skill`、`workday`、`item`，或受支援模組的 `route`。寫入檢查目前來源權限；保存引用不授予額外讀取權。原資料之後被撤銷或刪除，總覽讀取仍會按目前權限拒絕，不用舊快照冒充內容。

## Codex 的修改方式

目前對話需真正載入並獲准使用同一工作台的工具：

1. 用 `blueprint_workspace_info` 核對工作室網址及帳戶。
2. 用 `blueprint_get_presentation({key:"overview"})`，或讀取所需 `page:<route>`／`pins`。
3. 在讀回的 `data` 上只改使用者要求的欄位，保留其他卡片及設定；保留該文件版本。
4. 用 `blueprint_update_presentation` 傳入 `key`、該版本作 `expected_version`，以及完整文件的 JSON 字串 `data_json`。
5. 再呼叫 `blueprint_get_presentation` 核對相同 key、版本及內容；網頁會按同步狀態接收。

這是日常私人偏好保存，不需要修改 GitHub 或部署。改顯示標題不等於修改正式項目名稱；要求修改公司紀錄時仍使用相應業務工具。新版工具目錄有 42 個共通工具；原生／Sites 原生接駁另有六個擁有人維護工具，共 48 個。工具目錄更新與後台已部署、目前對話已載入，是分開的驗收項目。

## 舊版偏好、離線及備份

原有 `blueprint-workspace-v2`、`blueprint-page-layouts-v1`、總覽引用及原始備份鍵保留。首次成功讀取同步後台時，只可在遠端尚無該文件的情況匯入本帳戶既有本機配置；已有遠端版本不能被另一部裝置的舊快取無聲取代。尚未保存的本機修改按同一網站、帳戶及分頁識別碼保留。重新載入可取回原分頁的草稿；新分頁或新導覽使用另一識別碼，避免兩個分頁覆蓋彼此的離線修改。重新連線後先核對遠端版本。

同步後台把資料放在原有 `studio_preferences.data._presentation` 保留欄位，資料格式維持 **schema 7**，不用建立另一個資料庫。普通偏好 API 不回傳此欄位，也不接受呼叫者直接寫入；普通設定更新必須保留最新的版面資料。兩種設定各有版本，不因另一種設定更新而互相覆蓋。

完整後台備份包含已同步版面；尚未送出的修改、瀏覽器專用顯示選項及舊版原始備份仍需在原瀏覽器另存。清除網站儲存會移除本機未同步修改。

「還原排版」會先檢查同一網站及帳戶、備份格式和支援欄位，再保留還原前的本機與帳戶版面。只把備份的主要總覽、各頁配置及來源引用轉成版面文件；歷史備份鍵不會被當成另一份待同步配置。支援同步時，使用目前文件版本保存，完整讀回並核對所有還原內容後才重新開啟頁面。期間若離線、衝突或僅部分保存，保留備份與待送修改並顯示未完成，不假裝其他裝置已全部還原。

後台完整備份還原與瀏覽器排版匯入是不同操作。後台還原令版本或內容分歧時，先依上述「重新核對版面版本」流程處理，再決定如何保留本機草稿；不要只用版本號推斷待送修改已經保存。

## Sites 適配與更新

原生 Python 提供以上 API。純 Sites 需將 `integrations/sites/presentation.mjs` 接入原 Site 的身份、正式儲存及寫入規則，不能只換前端檔案就宣稱同步完成。

模組提供：

- `createPresentationHandler({storage, authorize, authorizeReference})`：處理版面路由；`authorize` 驗證現有平台登入後回傳 `{username, readOnly?}`，`authorizeReference` 核對目前來源權限。
- `createD1PresentationStorage(db, {defaultPreferences?})`：只適用已有 `studio_preferences(username,version,data)` 結構的 D1；不建立或重設資料表。首次只保存版面時提供普通偏好預設值，宿主可傳入自己的預設值函式。
- `readOrdinaryPreferences(storage, account)`：讀取普通偏好，隱藏保留欄位 `_presentation`。
- `saveOrdinaryPreferences(storage, account, expectedVersion, values)`：供原普通偏好保存路徑採用，或實作等價的完整列原子比對以保留 `_presentation`。
- `validatePresentation(key, value)`：使用有上限的版面資料格式驗證。

原 Site 必須同時處理普通偏好讀取時隱藏 `_presentation`、首次只有版面資料時仍返回普通預設偏好，以及來源讀取的原有權限。完成相同帳戶、跨帳戶、過時分頁的身份標頭、競態、重啟和保存讀回驗收後，才宣告 `presentation_sync` 能力。其他儲存模型可提供相同原子儲存介面，不能拿新的空白資料庫代替現有公司資料。

Sites 入口配原生後台時，需核對新資產白名單、工具目錄及實際代理路由；保留原網址、身份對應和儲存。使用不支援的後台會回到明確標示的本機保存模式；這不是跨裝置同步成功。

## 驗收

以隔離測試帳戶核對：同一帳戶兩個獨立瀏覽器及 MCP 寫入讀回、另一帳戶隔離、相同欄位衝突、不同欄位整合、離線後接續、舊本機配置匯入、編輯草稿保留、背景分頁、卡片引用撤銷，以及與普通偏好同時保存、後台還原分歧與排版備份還原讀回。再核對手機閱讀不改寫桌面配置、重啟後保存及備份內容。

開源程式及本機測試不代表任何私人測試工作室已部署。正式更新仍按[同站更新流程](UPDATE_ROUTE.md)保留資料、登入、附件、網址及權限，並在真正工作室重做讀寫驗收。
