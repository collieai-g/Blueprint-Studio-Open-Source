# 開發驗收與證據

[參與貢獻](../CONTRIBUTING.md) · [開發流程](DEVELOPMENT.md) · [私隱規則](PRIVACY.md) · [共用生命週期](INSTALL_UPDATE_FLOW.md)

開源修改按 `source_release` 路線交付通用來源、文件、必要檢查及可審閱 PR。這條路線不連接私人工作台、不寫正式資料，也不部署私人服務。範圍若日後包含原站更新，再使用 [UPDATE_AI.txt](../UPDATE_AI.txt) 與原站的私人進度。

## 按風險選擇檢查

| 修改範圍 | 需要的證據 |
| --- | --- |
| 文件、Issue／PR 範本 | 指令及能力描述對得上來源；相對連結、YAML 格式與表單欄位有效；公開內容審核；diff 無格式錯誤 |
| 前端行為或載入 | 相關 Node 測試、必要瀏覽器重現；依 AGENTS.md 重建網頁產物；保留導覽、表單草稿、登入帳戶隔離與衝突處理 |
| HTTP／MCP／Agent 合約 | 相關 Python／Node 與合約測試；權限、版本衝突、重試和同 ID 讀回；固定 Blueprint、Agent 與接駁層版本 |
| 持久層、schema、登入或附件 | 相關回歸、合成舊資料升級、完整備份與隔離還原測試；沿用原生生命週期，不以筆數相同代替內容核對 |
| 效能 | 相同來源、資料規模、環境與操作的修改前後結果；冷／暖啟動、切頁、儲存或同步的耗時及請求數；同時通過正確性檢查 |

以上是選擇相關驗證的最低依據；仍遵循 `AGENTS.md` 及現有 CI 的要求。文件 PR 不需要為了收集證據建立正式服務或寫入私人資料。未修改的功能沒有因此取得新的實際驗收證據。

效能數字要註明測量方法、樣本數及測試資料規模。單次感受或本機比雲端快，不能證明問題已解決；尚未量測時不承諾固定秒數。減少讀取仍須保留權限檢查、版本檢查、草稿和必要讀回。

## 缺陷留下可重複驗證的案例

AI 從使用者描述整理案例，優先沿用既有測試、案例登錄及共用 runner。同一根因追加原案例的觀察與版本，不每次另造案例或另一套執行器。案例至少能定位：

- 穩定案例編號、所屬來源與受影響功能。
- Blueprint、Agent 及接駁層的固定版本組合，或開發候選的輸入指紋與相關環境；未知項明列未知。
- 合成資料、必要設定、操作步驟、預期與實際結果，以及可核對的成功條件。
- 實際執行的檢查、修正前後結果及限制；完整來源／環境／產物證據留在相應收據，私人材料依私隱規則另存。

這些是案例內容與證據要求，沿用既有欄位、測試及收據引用，不表示已新增 case schema 或自動產生案例的工具。

對可重現缺陷，優先以同一合成條件取得「修正前失敗、修正後通過」；依賴缺失、環境錯誤或未能重現不能冒充產品失敗。只有修正後證據時如實列出，不宣稱已證明原因。前端問題按風險核對真實瀏覽器操作與保存後讀回，不能只比對原始碼或畫面文字。純文件／低影響改動沿既有文件檢查，不為每句文案建立形式化測試。

新功能以已約定行為為準。已授權的介面替換同步更新功能對應與測試；不得為了通過而弱化資料保留、權限或人工控制等要求。相關修改重跑受影響案例，仍遵守既有必需檢查與 CI；精確選測尚未實作時不能自行縮減 manifest 的 inputs 或跳過依賴不明的檢查。

模型參與的行為案例，記錄可取得的模型、提示／Skill、合成知識與工具條件，按風險重複執行並報告各次結果。評估實際保存狀態、工具動作及語意標準，不要求回覆逐字相同；模型評分需由人工樣本校準，無法判斷保留未知。程式、瀏覽器及合成模型檢查均不冒充真實渠道送達或目前 AI 的工具驗收。

## 每項結果明確寫狀態

使用「通過、失敗、未執行、不適用」，並附命令或核對方式及原因。需要外部能力但尚未取得時，另外寫具體缺項及下一步；結果未知先查回，不能記成通過。靜態合約檢查、mock、合成測試及真實服務驗收分別標明。

檢查紀錄綁定實際來源或輸入 tree、命令、環境與適用的產物雜湊；只在相關輸入相同時沿用。來源凍結後完成正式驗證，再將結果寫入 PR 或檢查收據，避免為了把自己的 commit 寫回文件而循環提交。`tools/lifecycle_plan.py` 的 inputs／reuse 見 [LIFECYCLE_API.md](LIFECYCLE_API.md)；工具不會代為執行檢查或認定操作者輸入的結果為真。

交付按本次範圍說明問題／案例、修改去向、被測來源及產物、實際檢查與未完成項。若包含測試台更新，另外核對原目標真正載入相同候選、同 ID 資料與必要功能讀回，以及資料保留；來源通過、計劃通過與更新完成分開記錄。結果未知先查回，同一計劃沿原操作續行，有效證據按現有指紋與備份 coverage 規則重用。

公開範例：

```text
任務：source_release
來源：PR 的固定 head commit；Agent／adapter 另列公開固定來源或不適用
範圍：文件與範本
檢查：git diff --check；通過
檢查：Issue 表單 YAML 與相對連結；通過，附實際方法
網站部署：不適用，本 PR 不部署
目前 AI 寫入與讀回：不適用，本 PR 沒有接駁私人服務
限制：尚無實際網站或渠道驗收
```

這只是格式示例，不能複製作為本次已通過的結果。私人來源、實際資料 ID 與備份證據按[私隱規則](PRIVACY.md)另存。

## Agent 與 AI 接駁逐層驗收

| 層次 | 完成標誌 | 仍未證明 |
| --- | --- | --- |
| 套件來源與靜態預檢 | 固定來源及 manifest 合約檢查通過 | 已登記、執行或接通外部服務 |
| 私人後台登記 | 經授權保存並讀回同一套件／實例 | 目前 AI 已載入工具或背景服務在運行 |
| 目前客戶端能力 | 這次對話確實具有所選路徑需要的工具及授權 | 本次任務已成功保存 |
| 實際任務 | 同一後台建立工作，真實執行並保存；獨立讀回相同 ID、版本與結果，畫面可核對 | WhatsApp 送達、無人值守執行或未測試的渠道能力 |
| 外部服務 | 渠道／模型服務自己的實際執行、回執與必要重試核對 | 其他渠道、帳戶或之後的新對話均已驗證 |

採用 MCP 時按 [AI_CONNECT.md](../AI_CONNECT.md) 呼叫真正載入的工具；不能用直接 API 或瀏覽器操作冒充 MCP 驗收。採用已授權畫面控制時，如實記錄該路徑。兩者均不能用歷史測試代替目前客戶端的證據。合成合約測試不會觸發真實客戶訊息；對外發送依使用者授權另外驗證。

## PR、發版及實際更新分開交付

1. **可審閱 PR**：來源、範圍、必要檢查、未測項目及私隱核對齊備。
2. **合併／正式發版**：由維護者按既有政策處理，核對實際 tag、commit 及產物；開 PR 不代表已合併或發版。
3. **個別工作台更新**：獲授權後，按原站備份、整合、部署及持久性驗收流程完成；GitHub 推送不代表服務已更新。
4. **網站及 AI 狀態**：分開回報實際網站版本與目前 AI 真實寫入／讀回結果。無部署或接駁範圍時明確寫不適用，不宣稱完成。
