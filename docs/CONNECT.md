# 在左側 AI 完成接駁與驗收

[AI 接駁入口](../AI_CONNECT.md) · [安裝](INSTALL.md) · [技術接駁](AI_CONNECTION.md) · [保留資料更新](UPGRADE.md)

**V2.7.4 的接駁設定在左側 Codex 或你實際使用的 AI 客戶端完成。** 右側只提供公司的工作介面，不需要開啟接駁精靈、選模型或保持測試卡片開啟。已有設定便核對後沿用。

## 先交給左側 AI

把 [AI_CONNECT.md](../AI_CONNECT.md) 交給目前對話，連同自己的工作台地址。AI 按入口核對實際能力、正確公司與網址、登入授權，再選擇畫面控制或 MCP。沒有登入或控制能力時，由 AI 說明目前缺少的一步，不把可見網頁當成可以操作。

- **畫面路徑：** 目前客戶端真正能控制同一個已登入工作台時，用正式表單保存已授權內容，再重新開啟相同紀錄核對；這不是 MCP 接駁驗收。
- **MCP 路徑：** 由左側 AI 安裝或沿用相容設定，完成授權並確認目前對話已載入實際工具。使用同一個已驗證後台及原有資料，不另建資料庫。

後台仍處理身份、權限、版本、附件及持久儲存。接駁檔、工具清單和可見網頁各自只證明其本身；真正保存後按同一紀錄編號讀回，才證明當前路徑可用。

## MCP 的真實驗收

由使用者要求安裝／接駁並授權測試後，按 `AI_CONNECT.md` 由目前 AI 客戶端建立本次測試參數：

1. 讀 `blueprint_workspace_info` 及 `blueprint_connection_guide`，核對正確工作台、實際客戶端和目前規則。
2. 用客戶端的密碼學隨機來源產生 16 bytes，編碼為 32 位小寫十六進位 `challenge`，連同實際 `client` 和日期 `date` 私人記錄。重試沿用相同參數，不為繞過衝突而換識別。
3. 只透過目前真正載入的 `blueprint_verify_connection` 執行驗收。工具保存標題為「AI 接駁測試」的工作及待辦，讀回、以版本檢查更新待辦，再讀回完成結果。
4. AI 以 `blueprint_get_workday` 按返回的工作編號重新讀取，再用 `blueprint_list_todos` 核對相同待辦及 `workday_id`，確認 challenge、來源、日期、完成狀態及驗收標記。
5. 在右側打開同一紀錄；外部保存後按「更新資料」即可。沒有右側控制能力時，由使用者核對，畫面結果另列為待確認。

不需要從瀏覽器精靈取得參數，也沒有每五秒的右側驗收輪詢。下載 `AI_CONNECT.md`、安裝外掛、接通工具、測試完成和畫面核對分開回報。不得透過瀏覽器或直接 API 偽造 MCP 驗收標記。

完成後再做一項使用者真正要求的文件、收藏或工作任務，保存後讀回，交付實際位置及編號。新對話重新核對當前能力；舊測試不是持續連線保證。

使用者要求記錄月曆工作時，原生及 Sites 原生接駁可先用 `blueprint_calendar_meta` 核對員工與權限，再讀 `blueprint_calendar_month`。建立工作／待辦沿用同一 `request_key`；修改帶最新版本，保存後再讀月份核對相同 ID。月曆工具不代替上述接駁驗收，也不提供代使用者打卡的操作。純 Sites 的 42 個共通工具保持原合約，未因介面載入便具備原生月曆能力。

## AI 應保留的私人接續記錄

記錄正確工作台、客戶端及路徑、設定位置、授權狀態、challenge／client／date、測試紀錄編號、真正讀回結果與尚缺的畫面核對。密碼、token、完整聊天及公司材料不放公開倉庫。

`blueprint_connection_guide` 和同站已授權的 `/connection-guide.json` 提供相同規則。每個使用工具的新對話先讀取；支援私人專案指引的客戶端可記下工作台地址及入口，保留原有設定。

只讀 MCP 不提供寫入驗收。無效參數不寫入；使用者改動測試紀錄時停止核對原狀，不覆寫。測試使用原工作及待辦資料表，納入既有完整備份；沒有新增 schema 或模型執行器。

## 遇到問題時

| 情況 | 左側 AI 接續甚麼 |
| --- | --- |
| 外掛已安裝，對話沒有工具 | 核對目前客戶端是否已選用並授權該工作台工具；必要時按平台流程重新載入，不反覆安裝。 |
| 401／403 或登入失敗 | 核對同一網站與帳號；403 亦可能是來源或角色權限，按實際錯誤處理。 |
| 網絡政策拒絕或逾時 | 分清平台工具與執行環境 HTTP，檢查支援的網絡設定；保留代理及 TLS，不繞過平台限制。 |
| 工具舊版或 404 | 核對正式後台及工具程式版本；只有使用者要求更新時才走原服務更新流程，不因接駁而自動部署。 |
| AI 說已存，右側未見 | 比對網址、公司、帳號及紀錄編號，先讀回再按「更新資料」，不另建空資料庫或重複保存。 |
| 草稿或來源已改變 | 保留修改，重新讀取並整合版本；不要用新 challenge 或重複紀錄避開衝突。 |

## 部署者的相容要求

完整包及介面包包含 `AI_CONNECT.md`。按目前部署方式提供已驗證身份下的接駁檔、`connection-guide.json` 及既有 MCP 描述／工具定義；原生與 Sites 授權方式分開核對。

Sites 適配器使用原來的身份、API、儲存及工具合約。右側精靈退場不表示要移除共用驗收工具、另建資料庫或放寬權限。更新 GitHub 也不代表任何私人或測試工作台已部署。
