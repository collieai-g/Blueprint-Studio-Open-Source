# V2.4｜從工作台完成 AI 接駁

[最簡單安裝入口](../START_HERE.md) · [技術接駁](AI_CONNECTION.md) · [保留資料升級](UPGRADE.md)

這是安裝的最後一段，也是日後換 AI 或換對話的接續入口。由同一個正式工作台的「AI 接駁中心」開始，AI 陪同完成設定、真正工具讀寫、畫面顯示及第一項工作。

## 使用者只需做目前一步

1. 開啟並登入自己的工作台，按首頁「開始 AI 接駁」或左下方「AI 接駁中心」。
2. 選使用中的 AI 客戶端及工作台安裝方式。原生後台會自動選原生路線；Sites 選 Sites。其他客戶端填實際名稱。
3. 按「複製接駁及測試指令」，貼到使用中的 AI。指令包含同一網站地址、所選客戶端、接駁路線及本次測試識別；沒有帳密。
4. AI 先做能執行的設定。需要你登入、授權或選用外掛時，它提供目前入口、要做的動作及成功標誌。完成後回到原步驟。
5. 保持接駁中心開啟。AI 完成驗收工具後，這裏會每 5 秒從原後台檢查結果，顯示相同紀錄的來源、ID、時間及完成狀態。按「查看測試紀錄」可在每日工作查閱。
6. 選「整理一份文件」、「保存學習資料」或「整理工作及待辦」的範例，交代真實內容。AI 保存後讀回確認；回到正常工作台，可見且沒有草稿時約 10 秒同步。

每個客戶端有自己的測試識別及進度。瀏覽器只保留選擇和測試識別；驗收紀錄存在原後台資料庫。重新開啟中心會重新讀取，並非單靠 localStorage 顯示已接通。清除瀏覽器資料或換帳號、對話後，重新建立測試指令；不刪除既有工作或舊測試。驗收時間代表當次結果，不是持續連線保證。

## 安裝 AI 必須完成的工作

- 先讀安裝包的 INSTALL_AI.txt、AGENTS.md、安裝／升級路線，再完成真正網站；維護私人 INSTALL_PROGRESS.md。
- 同一網站必須提供完整 V2.4 UI，包含 /connection.js 及 /connection-guide.json。不得在打開網頁後停止。
- 原生路線安裝 MCP 專用依賴、合併客戶端設定及秘密變數參照；Sites 路線取得同一 Site 的真實 plugin_id、mcp_url、oauth_resource 並刷新工具。具體配置見 [AI_CONNECTION.md](AI_CONNECTION.md)。
- 各個新對話先呼叫 blueprint_workspace_info，再呼叫 blueprint_connection_guide。後者直接讀取與工作台共用的內置規則；把後台地址及如何讀取規則合併到客戶端支援的私人專案指引，保留既有指引，不假設所有產品都有同一記憶機制。
- 由使用者啟動接駁中心，或明確授權安裝驗收後，使用中心提供的 challenge、client、date 呼叫 blueprint_verify_connection。不要自行猜測或換識別碼躲避錯誤。
- 若 AI 無瀏覽器工具，提供本頁的一個明確檢查動作，將畫面驗收記為待使用者確認；不能聲稱看過實際右側。
- 完成後交付網站、版本、客戶端、設定位置、測試紀錄 ID、工具結果、右側結果及第一項真實工作。只完成一部分就回報具體卡點。
- 普通聊天未有工具時，只引導目前一步，或將無秘密的交接包交給有工具的 AI，不標記安裝完成。

## 六種卡點的接續規則

| 情況 | 下一步 |
| --- | --- |
| 外掛已安裝，對話沒有工具 | 在目前對話選用工作台外掛並登入；必要時重新連接或以選好外掛的新對話接續。不要反覆安裝。 |
| 登入失敗、401、403 | 核對同一網站及帳號；Sites 使用平台登入，原生使用安全環境變數。403 也需核對來源及寫入權限。 |
| 網絡政策拒絕、逾時 | 辨認是平台外掛還是執行環境直接 HTTP；後者檢查目前生效允許清單，經平台設定加入精確工作台網域及實際所需登入網域，完成平台要求的審核後重新驗證。保持代理與 TLS。 |
| 舊工具、缺少新版工具、404 | 更新同一後台、工具程式及前端到 V2.4；Sites 更新外掛定義並重新載入。不能只換前端或 GitHub。 |
| AI 說已存，但右側沒有 | 比對工具回傳網址、公司及登入帳號；按返回 ID 查同一後台。不要另外建立空資料庫。 |
| 畫面未同步 | 關閉草稿／卡片編輯，保持頁面可見，查同步錯誤。資料已存在時不要重複保存。 |

平台外掛的遠端呼叫不等於從 AI 的雲端程式執行環境發 HTTP。兩條路分開檢查；放行環境網絡不會自動載入對話工具。工作台不修改平台的登入、工具選擇或網絡政策。

## 驗收如何運作

blueprint_verify_connection 使用正常的 /api/workdays 及 /api/todos：
- 搜尋同一日期、客戶端及 blueprint-connect:challenge，重試沿用同一筆紀錄。
- 保存標題「AI 接駁測試」的工作及一項測試待辦。
- 分開 GET 讀回；使用 expected_version 更新測試待辦為完成，再讀回。
- 保留項目 ID、完成狀態及歷史，寫入驗收標記，再次讀回返回 ID。
- 工作台獨立搜尋及 GET 同一筆紀錄，核對完整識別、來源、日期、項目及完成狀態才顯示完成。錯誤／部分成功不顯示已完成。

只讀 MCP 連接不提供也不允許此工具。無效參數不寫入；使用者改動測試紀錄時停止並提示建立新測試，不覆寫其內容。接駁驗收沿用原工作紀錄表；V2.4 公司功能另有 schema 5 新表，正常備份亦包含驗收紀錄。這是可重做的功能驗收，不是防竄改的審計憑證或持續連線監測。

## Sites 安裝者必須打包的檔案

沿用原 Site ID、平台登入、使用者隔離、資料庫與附件，按 package_workbench.py 清單整合：
- library_web/ 的完整檔案及 icons。
- integrations/mcp/tools.json、sites.mjs、connection.mjs 放在同一模組目錄。
- /connection-guide.json 由同一已授權網站提供 JSON；/connection.js 提供 JavaScript。
- 原 /api/info 可加入 connection_mode: sites；原生值是 native。這是引導預設，不是連線證明。
- 保留舊工具相容別名或按平台正式流程刷新外掛；確認兩個新工具已在目前對話可用。

MCP 適配器直接使用原有已驗證 API，因此沒有另建資料庫或模擬登入。仍須驗證正式 Site 的部署、OAuth／工具載入及右側結果；本機自動測試不等於每位使用者的正式帳戶已授權。
