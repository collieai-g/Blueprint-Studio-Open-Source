# 開發與公開回報的私隱規則

[參與貢獻](../CONTRIBUTING.md) · [開發流程](DEVELOPMENT.md) · [驗收規則](DEVELOPMENT_ACCEPTANCE.md)

本頁規範開源貢獻可以攜帶哪些內容。公司日常資料沿用原後台；安裝、備份與原站更新仍依[共用流程](INSTALL_UPDATE_FLOW.md)處理。公開倉庫不是私人工作台、診斷檔或備份的存放位置。

## 保存位置

| 內容 | 保存位置 |
| --- | --- |
| 通用程式、公開合約、文件、開發計劃、合成測試資料 | 對應的公開來源倉庫 |
| 公司專用程式與私人來源檢查點 | 經核實為 Private 的獨立來源倉庫；先按[來源檢查點規則](SOURCE_CHECKPOINT.md)審核內容 |
| 公司紀錄、客戶對話、知識內容、Agent 實例設定、工作輸入與結果、附件 | 私人後台或獨立私人資料位置；放在所有來源倉庫以外 |
| 密碼、金鑰、token、Cookie、登入與渠道憑證 | 平台秘密設定或安全輸入；不放聊天、Issue、PR、測試 fixture 或 Git |
| 真實部署設定、服務識別、私人進度、排版接續檔、診斷原檔、資料備份與還原證據 | 有適當存取控制的私人維護位置；放在所有來源倉庫以外 |

Private GitHub 倉庫適合保存已審核的私人程式，亦不代替正式資料庫或完整備份。公開範本可以包含虛構設定和 `.env.example` 欄位，但不得帶入實際值。`.gitignore` 只協助避免誤加檔案，不會清除已追蹤檔案、提交歷史或 GitHub 附件。

## 公開報告採用最少內容

優先在乾淨測試環境建立合成最小重現。只公開人工檢查後的必要內容：

- 公開產品與合約版本、公開來源完整 commit，以及一般環境版本。
- 所屬元件、重現步驟、預期及實際行為。
- 合成輸入、無身份資訊的錯誤代碼，以及必要的短錯誤片段。
- 檢查命令、通過／失敗／未執行狀態、合成測試結果；效能回報可用不含正文或網址的耗時與請求數。

來源為私人或未知時，填「私人、不公開」或「未知」，不用為填表而公開倉庫、commit、工作台網址、帳戶、真實檔案路徑、資料編號或服務識別。完整來源證據保存在私人紀錄；公開報告說明仍欠哪類證據。

不要直接附上完整聊天、資料庫、備份 ZIP、私人來源包、瀏覽器儲存匯出、HAR、原始日誌或整張私人畫面。這些檔案可能包含表單正文、搜尋字詞、URL 參數、Cookie、Authorization 標頭、附件及檔案中繼資料。優先重新產生合成示例；需要截圖時，用合成內容重新拍攝，檢查網址列、帳戶、背景視窗及下載檔名。

目前沒有自動產生「可安全公開診斷包」的保證。遮蓋畫面、移除幾個關鍵字或掃描沒有命中，均不能自行證明整份資料可以公開。必要私人材料只在另行獲授權且已核實的私人渠道處理；本流程不會自動上傳。

## 提交前逐項核對

1. 列出本次允許公開的檔案，逐檔加入暫存區；不要從私人工作目錄執行全目錄加入。
2. 檢查 `git diff --cached --name-status`、`git diff --cached` 及 `git diff --cached --check`，包括新增檔、二進位附件及刪除內容。
3. 確認變更歷史沒有帶入私人提交。清空當前檔案不會清除舊提交中的內容；分享變更時採用乾淨公開基線，保留所需授權及來源。
4. 另行預覽 Issue／PR 正文、評論、截圖與附件；它們不受本機 `.gitignore` 保護。
5. 只有明確可公開的內容才提交。無法判斷的欄位留「未提供」，交代對重現或驗收的限制。

如果發現已公開憑證，先停止繼續傳播，撤銷或輪換受影響憑證，再處理公開檔案、附件及歷史；不要在公開 Issue 重貼秘密來描述問題。

## 公開範本的界線

本倉庫的 Issue 與 PR 範本是填寫指引，不會自動移除私人內容或授予上傳權限。公開開發計劃只記通用範圍、依賴與驗收標準；私人工作台的網址、備份位置、實際登入及進度另存。實際部署或 AI 接駁的私人驗收結果，與公開來源測試分開保存和回報。
