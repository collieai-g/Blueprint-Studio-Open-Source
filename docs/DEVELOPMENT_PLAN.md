# 開發流程與操作改善計劃

[參與貢獻](../CONTRIBUTING.md) · [開發流程](DEVELOPMENT.md) · [驗收規則](DEVELOPMENT_ACCEPTANCE.md) · [私隱規則](PRIVACY.md)

目標是讓使用者和協作 AI 能把操作問題轉成可重現、可測試、可審閱的通用修正。計劃只包含公開產品內容，不保存個別工作台的網址、來源、自訂設定、資料或進度。

工作室核心、客服 AI 與客戶專用模組的背景準備、獨立換版及統一更新入口，另見[更新功能開發計劃](UPDATE_SYSTEM_DEVELOPMENT_PLAN.md)。該計劃自第一版設計元件獨立更新，並說明既有架構可按新需求調整；以下歷史批次不限制新功能的開發次序。計劃交付不代表更新器已實作或任何工作室已部署。

規劃基線：公開 v2.9.0，commit `af60227225ee5bacc0d2ac99933f8a7f01da4d1d`。後續實作開始時重新核對 main、相關 PR 與相容性，不將本頁基線當成永久最新版本。

## 第一批：開發流程與貢獻入口

本批範圍為文件與 GitHub 範本，沿用現有 `source_release` 路線，不改執行期程式、產品版本、schema、部署工作流或現有網站。

| 交付 | 驗收 |
| --- | --- |
| CONTRIBUTING.md 與開發指南 | 從 README／START_HERE／AGENTS 可到達；說明資料操作、程式開發、發版及部署的分工 |
| 問題回報與功能建議表單 | 可填版本、所屬元件、合成重現、預期／實際結果及驗證限制；不要求私人網址或日誌包 |
| PR 範本 | 描述問題與修正、相關來源、實際檢查與未測項目，分開標明部署與 AI 驗收 |
| 驗收及私隱規則 | 檢查按修改風險選擇；結果不得冒充實際接通；私人內容與備份留在來源倉庫以外 |
| 公開計劃與可審閱 PR | 本批變更可獨立審閱，列出檢查及限制；未經後續決定不合併或發版 |

完成本批不會建立新的測試工作台、搬遷資料、接入客服渠道或部署服務。計劃與範本是流程指引，沒有新增自動診斷、同步或 Agent 執行能力。

## 四項開發規則與待補程式能力

[開發指南](DEVELOPMENT.md)已規定直接修正負責來源、留下可重複案例、透過正式入口保留原實例更新，以及由 AI 接續已授權工作；[驗收規則](DEVELOPMENT_ACCEPTANCE.md)定義案例與證據。這些是開發行為要求，以下能力仍須實作與驗證，沒有因文件更新而完成，也不授權部署任何工作室。

| 待補能力 | 負責來源及已有基礎 | 尚缺內容與完成標誌 |
| --- | --- | --- |
| 配對來源的隔離開發預覽 | 藍圖來源已有[單來源開發預覽入口](DEVELOPMENT.md#預覽目前藍圖來源)，使用獨立合成資料 | 仍須加入獨立 Agent 來源配對、資產重建與相容性檢查；記錄真實來源指紋，不以虛構遠端 commit 通過正式登記。修改能在預覽核對並從相同來源重建 |
| 既有 Agent 套件正式升級 | 本機來源已提供[同 ID PATCH 升級](AGENT_CONTRACT.md#既有-agent-套件升級)，具 CAS、原設定保留、交易式歷史與重試收據；合成回歸核對備份還原及舊工作快照 | 個別平台／運行宿主尚須部署與實測；目前只處理相容設定，移除已保存欄位、變更共同欄位類型或值不相容時仍需處理。外部 runtime／資產更新、瀏覽器未保存草稿的恢復亦須另行驗收，不能將來源測試當作實例已換版 |
| Agent 與宿主的升級接駁 | BlueSAI 來源已有指定 `expected_agent_id`／`upgrade_key` 的同 ID 更新接駁，舊宿主缺能力仍拒絕更新 | 核對實際宿主支援後，驗證相容性、獨立服務／資產替換及原資料讀回；未影響宿主的 Agent runtime 變更只更新所需服務，不重建卡片或部署整套工作室 |
| 來源修正至指定測試台的自動接續 | 現有唯一共用 runner、更新助手、維護操作紀錄及私人綁定 | 用薄入口串起案例、來源組合、測試產物與已授權目標更新；中斷後只續未完成部分，未知結果先查回；缺能力如實待辦。`update-check` 仍是計劃檢查，不作部署引擎或成功證據 |
| 依變更影響選測及證據重用 | 現有 CI、輸入指紋、收據與 [Harness 候選](HARNESS_VALIDATION_NEXT.md) | 建立可驗證依賴與選測入口，來源或依賴改變會令相關收據失效；保留既有必需檢查與完整 CI，不靠刪除 inputs 提速。從常見真實缺陷建立合成案例並納入既有檢查 |
| 模型行為評估與人工抽查 | 各 Agent 的既有測試；更廣泛評估仍屬後續候選 | 固定合成知識與工具條件、可知模型／提示版本及語意標準，記錄多次結果並以人工樣本校準；與資料持久性、UI 操作及真實渠道驗收分開，不以一次漂亮回覆宣稱可靠 |

優先以一個已知缺陷走通來源修正及回歸，再補配對預覽與同 Agent 升級所需能力，最後把已驗證入口接續起來；不另建總管平台或第二套 runner。各項需在開始實作時核對最新來源與既有能力，未完成部分持續保留在清單。

## 後續候選：先量測，再改善操作

以下均為待評估項目，不是本批已實作能力，也不承諾發版日期或效能數字。

| 次序 | 待處理內容 | 實作前依賴及完成標誌 |
| --- | --- | --- |
| 2 | 開頁、切頁、儲存及同步的量測；減少不必要的初始與重複讀取 | 先定位原生後台、前端、Agent 或平台接駁層；記錄相同條件的前後耗時／請求數，保留草稿、權限及版本保護 |
| 3 | 可預覽、由允許欄位組成的去敏唯讀診斷 | 先設計資料邊界和人工檢查；合成測試證明不包含正文、帳戶、網址、標頭或附件；不自動上傳 |
| 4 | 本機 Agent 來源及相容性檢查 | 藍圖單來源預覽已提供獨立資料／備份；Agent 來源配對仍待補，不虛構 GitHub commit；固定 Blueprint／Agent 配對並做乾淨環境和 Windows 驗證 |

效能工作先審閱既有 [PR #7](https://github.com/collieai-g/Blueprint-Studio-Open-Source/pull/7)。其提案涉及按需讀取與通用 D1 儲存，原基線為 V2.7.2；重新確認狀態、逐項選取適用改動並對目前基線重測。PR 文字中的測試結果不直接視為新整合的證據，通用儲存模組亦需各平台真正接入。某個私人接駁層的問題不能直接歸因於公開原生後台。

本機／雲端完整業務資料雙向同步是另一個產品議題，涉及衝突、身份、附件與離線回復，不作為上述開發流程的前置條件。日後要做時另立範圍和驗收。

## 之後怎樣接續

每次選一個可獨立驗證的問題：先用範本記錄，再按[開發指南](DEVELOPMENT.md)定位和修正。已存在的 PR 先審閱；新方案記錄依賴、驗收及限制。實作、合併、發版與私人工作台更新分階段記錄，私人進度不回填本頁。
