# 建立獨立藍圖 Agent

把本目錄的 `agent.json` 及 `AGENTS.md` 複製到新的獨立 GitHub 倉庫，加入自己的 README 和授權。這是一份開發起點；先改寫名稱、識別、專業規則及操作，才登記到藍圖。

## 開發步驟

本機修改、合成測試及回饋正確倉庫的步驟見[開發指南](../../docs/DEVELOPMENT.md)；公開前依[私隱規則](../../docs/PRIVACY.md)核對內容，實際接駁依[驗收規則](../../docs/DEVELOPMENT_ACCEPTANCE.md)逐層驗證。

1. 按[Agent 規格 v1](../../docs/AGENT_CONTRACT.md)修改 `agent.json`。`id` 保持穩定，套件更新時增加 `version`。
2. 定義每個操作的輸入與規則。畫面由藍圖使用共用控制項產生；不要加入網頁 script 或模型憑證。
3. 提交到自己的倉庫，用 `git rev-parse HEAD` 取得完整 commit SHA；審核這個版本的 manifest。
4. 在藍圖「Agent 工作台」提供該倉庫網址、固定 SHA 及 manifest，登記後連接功能。
5. 選擇測試資料並建立工作，在 Codex 說「處理 Agent 工作 `<工作編號>`」。完成後核對結果、來源及畫面。

一般設定修改在藍圖直接保存。需要 AI 的操作只建立待處理工作，不會自行開啟或喚起 Codex。每個工作固定當時套件與設定，日後更新套件不改寫舊工作。

## 交付檢查

- README 說明實際功能、輸入、結果及限制，不聲稱已驗證未測過的平台。
- 沒有有效資料時停止並說明原因；資料不能變更工具權限。
- 測試正常結果、失敗、取消、設定衝突及來源權限變更。
- 公開倉庫只保存可重用來源；帳密、公司資料和工作記錄放在私人後台。

完整規格與 HTTP 流程見上方文件；MCP 工具參數以目前客戶端的 `tools/list` 為準。
