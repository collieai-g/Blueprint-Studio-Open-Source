# 藍圖原生登入：通用參考修正交接

狀態：**供上游 PR 審閱的參考候選；未整合至原生登入、未正式發行。私人實例狀態另存。**

來源基線為 Blueprint Studio Open Source v2.9.0，commit
`af60227225ee5bacc0d2ac99933f8a7f01da4d1d`。
這份包提供可審閱的獨立登入接駁參考與回歸案例，沒有直接修改原版身份合約。

## 問題與預期行為

原生後台使用 HTTP Basic。有一次具體實測中，同一站點由 Chrome 可登入，
內置瀏覽器的提示卻立即關閉。安裝流程應先確認目前客戶端的登入能力，
提供經驗證的相容路線，不能只因網頁可開或單元測試通過便宣稱安裝完成。
目前公開資料不足以認定所有內置瀏覽器版本均不支援 Basic。

後續新增的表單接駁另曾引入一個可重現問題：登入頁使用 `no-referrer`，
導覽 POST 送出 `Origin:null`，被同源保護拒絕。這是新增接駁程式的缺陷，
不歸咎於原版 v2.9.0 沒有提供的 HTML 登入頁。

修正後，一般表單可先由既有後台核對原帳密，再載入原版完整工作台；
不改公司資料、不移除原 Basic/API/MCP 路線，也不複製其他瀏覽器登入狀態。

## 參考修正的界線

- 登入頁使用 `Referrer-Policy: same-origin`；代理原版頁面保留其政策。
- 同時核對 Host、Origin、nonce，拒絕缺少、null、外來及多值來源。
- 後台及入口只接受明確選定的 loopback 地址，連接埠與標題可設定。
- session、上游認證只留在記憶體；cookie 為 HttpOnly、SameSite=Strict，
  有期限、撤銷及重新登入處理。不把密碼寫入日誌、參數或檔案。
- 每個代理請求繼續由既有後台驗證身份；保留版本與角色保護、必要標頭、
  檔案上載及下載串流；不跟隨外部轉址。
- 本機 HTTP cookie 無法按 port 隔離，這份參考限於受信任的本機環境。
  如改作雲端入口，必須另行設計 HTTPS、Secure cookie、信任邊界與部署合約。
- gateway 重啟或登入階段到期需要重新登入，不表示公司資料失效。

## 建議上游整合順序

1. 先將客戶端能力核對及可見的登入錯誤納入安裝指南。
2. 審閱參考接駁實作，決定是否保留可選獨立入口，或在原生服務內提供
   等價的 cookie 表單登入；保留 Basic/API/MCP 向後相容。
3. 如整合進原生服務，沿用既有身份、角色、版本及持久儲存，不另建公司資料庫。
4. 執行合成安全回歸及真正瀏覽器表單回歸；凍結測試來源、命令、runtime
   及證據指紋。測試報告不能只靠手工填入一個 passed 欄位。
5. 以公開來源 PR 審閱及正式發行；私人實例更新再走原有備份、部署及驗收流程。

## 必須保留的回歸

```sh
python -X utf8 -m unittest discover -s tests -v
```

涵蓋登入政策、nonce、Host／Origin、錯誤帳密、節流、期限、撤銷、上游失效、
下載串流、必要標頭及轉址。具體測試數以當次 runner 收據為準。
另依 `cases/blueprint-login-001/README.md` 在真實支援的瀏覽器執行：

- 舊表單政策確實產生 null-origin 拒絕。
- 修正政策可以用虛構帳密完成瀏覽器登入。
- 保留獨立的 null-origin 拒絕檢查，不以放寬來源保護換取通過。

工作室名稱、登入資料、公司紀錄、附件及備份均不隨包分享。
